## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

Real scenarios solved end-to-end so you can see functions used the way you'd actually use them on the job.

### 1. Validate and normalize a deploy environment name

**Scenario:** Before running any deploy step, you want a single reusable function that checks the environment name is valid and returns a normalized version — instead of repeating the same `if` check in five different scripts.

```python
def normalize_env(env, default="dev"):
    allowed = {"dev", "staging", "prod"}
    env = env.lower().strip() if env else default
    if env not in allowed:
        raise ValueError(f"Unknown environment '{env}'. Choose from {allowed}")
    return env

print(normalize_env(" PROD "))   # prod
print(normalize_env(None))        # dev (uses default)
```
**Why it matters:** wrapping validation in a function means every script that needs it calls `normalize_env()` instead of copy-pasting the same check — one place to fix if the rules change.

---

### 2. Build a dynamic `kubectl label` command with `**kwargs`

**Scenario:** You want a helper that takes any number of label key/value pairs and builds the matching `kubectl` command, without hardcoding which labels exist.

```python
def build_label_command(pod_name, **labels):
    label_args = " ".join(f"{k}={v}" for k, v in labels.items())
    return f"kubectl label pod {pod_name} {label_args}"

cmd = build_label_command("web-app-7f9c8d", team="platform", tier="backend")
print(cmd)   # kubectl label pod web-app-7f9c8d team=platform tier=backend
```
**Why it matters:** `**kwargs` lets the function accept however many labels a caller needs — no need to predefine `team`, `tier`, `owner`, etc. as fixed parameters.

---

### 3. Generate sequential resource IDs with a generator function

**Scenario:** You need a stream of unique instance IDs for a batch provisioning script, without building the whole list in memory upfront.

```python
def generate_instance_ids(count, prefix="i-"):
    for i in range(count):
        yield f"{prefix}{i:04d}"

for instance_id in generate_instance_ids(3):
    print(f"Provisioning {instance_id}")
# Provisioning i-0000
# Provisioning i-0001
# Provisioning i-0002
```
**Why it matters:** `yield` produces IDs one at a time instead of building a full list first — useful when generating IDs for thousands of resources without wasting memory.

---

### 4. Retry-with-backoff using a nested function (closure)

**Scenario:** A deploy step calls a flaky API. You want a reusable retry helper that "remembers" its configuration (max attempts, delay) without passing those values around everywhere.

```python
def make_retrier(max_attempts=3, delay=1):
    def retry(action):
        for attempt in range(1, max_attempts + 1):
            try:
                return action()
            except Exception as e:
                print(f"Attempt {attempt} failed: {e}")
                if attempt == max_attempts:
                    raise
        return None
    return retry

deploy_retrier = make_retrier(max_attempts=2, delay=1)
result = deploy_retrier(lambda: "deployment succeeded")
print(result)   # deployment succeeded
```
**Why it matters:** `make_retrier()` returns a ready-to-use `retry` function that already has `max_attempts`/`delay` baked in — a closure — so callers don't have to keep passing config around.

---

### 5. Return multiple values from a health check for a CI gate

**Scenario:** A pre-deploy health check needs to report back both a pass/fail status and a human-readable reason, so the CI pipeline can decide whether to proceed.

```python
def check_service_health(cpu_percent, error_rate):
    if cpu_percent > 90:
        return False, f"CPU too high: {cpu_percent}%"
    if error_rate > 5:
        return False, f"Error rate too high: {error_rate}%"
    return True, "All checks passed"

healthy, reason = check_service_health(cpu_percent=45, error_rate=1.2)
print(f"Healthy: {healthy} — {reason}")

if not healthy:
    print("🛑 Blocking deploy")
else:
    print("✅ Proceeding with deploy")
```
**Why it matters:** returning a `(bool, str)` tuple gives the caller both the decision *and* the reason in one call — exactly what a CI gate needs to log and act on.

## 🔧 What is a Function?

A **function** is a block of code that performs a specific task.
You can define it once and call it multiple times, with different inputs.

---

## ✅ Syntax of a Function

```python
def function_name(parameters):
    # block of code
    return result
```

---

## 🧪 Example: Basic Function

```python
def greet():
    print("Welcome!")

greet()  # Output: Welcome!
```

---

## 🎯 Why Use Functions?

* Avoid repeating code (DRY)
* Modularize steps (e.g., `prepare_dough()`, `bake_cake()`)
* Improve debugging and testing
* Parameterize tasks (e.g., handle different sizes or settings)

---

## 💼 Real-World Use Case Example

```python
def make_pizza(topping, size):
    print(f"Making a {size} pizza with {topping}")

make_pizza("cheese", "medium")
make_pizza("pepperoni", "large")
```

## 🔢 Types of Functions in Python

---

### 1. **User-Defined Functions**

You create these yourself using `def`.

```python
def calculate_battery_percentage(used, total):
    return round((used / total) * 100, 2)

print(calculate_battery_percentage(45, 100))  # 45.0
```

### 2. **Built-in Functions**

Provided by Python, ready to use.

```python
print(len("kitchen"))          # 7
print(sum([10, 20, 30]))       # 60
print(type(3.14))              # <class 'float'>
```

---

### 3. **Lambda Functions** (Anonymous, One-liner)

Good for short, inline tasks.

```python
add = lambda x, y: x + y
print(add(5, 3))   # 8
```

✅ Use Case: Short logic in `map()`, `filter()`, `sorted()`, etc.

---

### 4. **Recursive Functions** (Calls itself)

Useful for nested structures or deep traversal (e.g., folder trees, family trees).

```python
def countdown(n):
    if n == 0:
        print("Done!")
    else:
        print(n)
        countdown(n - 1)

countdown(3)
```

## 🧠 What are Parameters and Arguments?

* **Parameters** are **placeholders/variables** listed in a function's definition.
* **Arguments** are the **actual values/data** you pass when calling the function.

---

### ✅ Example:

```python
def book_room(guest, room_type):   # Parameters
    print(f"Booking a {room_type} room for {guest}")
    
book_room("Riya", "Deluxe")  # Arguments
```

* `guest`, `room_type` → parameters
* `"Riya"`, `"Deluxe"` → arguments

---

## 🔢 Types of Parameters & Arguments in Python

| Type                       | Description                          |
| --------------------------- | -------------------------------------- |
| Positional                 | Based on position                    |
| Keyword                    | Based on name                        |
| Default                    | Have a default value                 |
| Variable-length `*args`    | Accept multiple positional arguments |
| Variable-length `**kwargs` | Accept multiple keyword arguments    |

---

### 1️⃣ **Positional Arguments**

Values are passed in the **exact order** of parameters.

```python
def water_plant(plant_name, section):
    print(f"Watering {plant_name} in {section}")

water_plant("Rose", "Garden-A")
```

⛔ If you change the order:

```python
water_plant("Garden-A", "Rose")  # Wrong!
```

---

### 2️⃣ **Keyword Arguments**

Specify the parameter name while passing values.

```python
water_plant(section="Garden-A", plant_name="Rose")
```

✔️ Order doesn't matter when using keyword arguments.

---

### 3️⃣ **Default Parameters**

You assign a **default value** in the function definition.

```python
def create_folder(name, location="Downloads"):
    print(f"Creating folder {name} in {location}")

create_folder("Photos")                 # uses default location
create_folder("Photos", "Documents")    # overrides default
```

✔️ Useful when a parameter is **optional** or has a **common default**.

---

### 4️⃣ **Variable-Length Positional Arguments: `*args`**

Use `*args` to pass **multiple values** as a tuple.

```python
def log_events(*events):
    for e in events:
        print("Log:", e)

log_events("Started", "Paused", "Finished")
```

✔️ You don’t know how many events you'll log — this handles it dynamically.

---

### 5️⃣ **Variable-Length Keyword Arguments: `**kwargs`**

Use `**kwargs` to pass a **dynamic number of named parameters** as a dictionary.

```python
def label_product(**labels):
    for key, value in labels.items():
        print(f"Label: {key} = {value}")

label_product(Name="Notebook", Category="Stationery", Owner="Riya")
```

✔️ Useful when labeling items dynamically (products, tickets, files, etc.)

## 🧠 What is Function Nesting?

**Function nesting** means defining **a function inside another function**.
The **inner function** is only accessible within the **outer function**.

---

### ✅ Syntax:

```python
def outer_function():
    def inner_function():
        # some logic
        pass
    inner_function()
```

---

## 🔍 Why Use Function Nesting?

| Benefit                | Explanation                                                                |
| ------------------------ | ------------------------------------------------------------------------- |
| 🎯 **Encapsulation**   | Inner logic is hidden and can’t be called directly from outside.           |
| 📦 **Modularity**      | Separate small tasks inside a main function.                               |
| 🔐 **Scoped Logic**    | Inner functions access outer variables but are not globally available.     |
| 🧪 **Real-World Use** | You can write utility functions scoped to a single task or workflow block. |

---

## 📦 Real Example – Step-by-step

```python
def book_trip(destination):
    def validate_destination():
        allowed = ["Paris", "Tokyo", "Cairo"]
        if destination not in allowed:
            raise ValueError(f"{destination} is not a valid destination")
    
    def run_booking():
        print(f"Booking a trip to {destination}")

    validate_destination()
    run_booking()

book_trip("Tokyo")
```

### 🔄 Output:

```
Booking a trip to Tokyo
```

---

## ✅ Explanation:

* `book_trip()` is the **outer function**.
* `validate_destination()` and `run_booking()` are **nested functions**.
* You **cannot call `validate_destination()` from outside** `book_trip()`.

---

## 🔐 Scope Rules in Nested Functions

Nested functions have **access to outer variables**, but outer functions **don’t access inner scopes**.

```python
def outer():
    msg = "Hello"

    def inner():
        print(msg)  # Accesses outer variable

    inner()

outer()
```

---

## ⚠️ Calling Inner Function Outside = Error

```python
def outer():
    def inner():
        print("Inner")

outer()
# inner()  # ❌ Error: inner is not defined
```

---

## 🔁 Nested Functions for Repeated Tasks

```python
def brew_coffee():

    print("Checking water level...")
    notify("Water low, refilling.")
    print("Brewing done.")
    notify("Coffee ready.")
```

```python
def check_appliance(device):
    def test_power():
        print(f"Testing power for {device}...")
```

## 💬 Can You Return a Nested Function?

Yes! This is often used in **closures** (useful in decorators, middleware, config-based functions):

```python
def wrapper():
    def inner():
        print("I'm inner")
    return inner

my_func = wrapper()
my_func()  # Output: I'm inner
```

| Feature             | Description                                   |
| --------------------- | ------------------------------------------------ |
| Defined Inside      | A function inside another function.           |
| Scope Restricted    | Inner function cannot be accessed globally.   |
| Uses                | Encapsulation, closures, scoped logic.        |
| Access to Outer Var | Inner can access variables of outer function. |

## 🔁 What is `return` in Python?

The `**return**` statement is used to **send data back** from a function to the caller.

* It **ends** the function’s execution.
* You can return **a single value**, **multiple values**, or **nothing** (i.e., `None`).
* Returned values can be **used or stored** in variables for further processing.

---

## ✅ Syntax

```python
def function_name():
    return value
```

---

## 📌 Why Return Is Useful

* Retrieve **results** or **IDs** from functions
* Perform **calculations** and use the result later
* Chain **steps** based on return values
* Validate logic and **unit test** your scripts

---

## 🧪 1. Returning a Single Value

```python
def get_favorite_color():
    return "blue"

color = get_favorite_color()
print(f"Painting the wall: {color}")
```

* Here, `"blue"` is sent back and stored in `color`.

---

## 🧪 2. Returning a Calculated Result

```python
def calculate_score_percentage(scored, total):
    return round((scored / total) * 100, 2)

score = calculate_score_percentage(65, 100)
print(f"Score: {score}%")
```

* You return a calculated value and reuse it for reports, alerts, etc.

---

## 🧪 3. Returning Multiple Values

You can return **multiple values** as a tuple.

```python
def get_book_info():
    return "Dune", "Frank Herbert", "Sci-Fi"

title, author, genre = get_book_info()
print(f"Title: {title}, Author: {author}, Genre: {genre}")
```

* Helps when you want a function to return **multiple details** in one go.

---

## 🧪 4. Returning Collections (List / Dict)

```python
def get_product_info():
    return {"Name": "Notebook", "Category": "Stationery"}

info = get_product_info()
print(info["Name"])  # Notebook
```

* Useful for grouping related details (products, records, files, etc.)

---

## 🧪 5. Returning `None` (or No Return)

If you don’t use `return`, Python returns `None` implicitly.

```python
def print_message(msg):
    print(msg)

result = print_message("Task started")
print(result)   # None
```

---

## 🧪 6. Early Exit with `return`

You can use `return` to **exit a function early**:

```python
def validate_size(size):
    allowed = ["S", "M", "L"]
    if size not in allowed:
        return f"Invalid size: {size}"
    return f"{size} is valid"

print(validate_size("XL"))
```

---

## 🔁 Return Inside Nested Functions

```python
def wrapper(mode):
    def validate():
        if mode != "weekday":
            return False
        return True

    return validate()

print(wrapper("weekend"))  # False
```

## 💥 Error Example: Trying to use result of a function that returns None

```python
def water_plant():
    print("Watering...")

status = water_plant()  # status = None
print(status.upper())     # ❌ AttributeError: 'NoneType'
```

✅ Fix:

```python
def water_plant():
    print("Watering...")
    return "success"

status = water_plant()
print(status.upper())  # SUCCESS
```

## 🧠 Best Practices

| Practice                                               | Why                        |
| --------------------------------------------------------- | ----------------------------- |
| Always `return` a value if further logic depends on it | Prevents `NoneType` errors |
| Prefer returning **dicts** for structured data         | Easier to parse, extend    |
| Avoid returning **print()** output                     | Print is side effect only  |
| Handle return values with proper checks                | Avoid runtime exceptions   |

---

## 📚 Summary

| Case                     | Return Type | Use Case                           |
| --------------------------- | ------------- | ------------------------------------- |
| `return value`           | Single item | One result (e.g., status, color)  |
| `return x, y, z`         | Tuple       | Multi-attribute result             |
| `return [list] / {dict}` | Collection  | Structured grouped results      |
| `return`                 | None        | Only for side-effects like logging |
| `return` (early exit)    | Conditional | Stop on error/invalid condition    |
