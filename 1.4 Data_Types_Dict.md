## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Turn an instance list into a fast lookup dict

**Scenario:** You get a list of instances back from a cloud API and need to look one up by ID repeatedly — a list would mean scanning every time.

```python
instances = [
    {'InstanceId': 'i-1111', 'Type': 't2.micro', 'State': 'running'},
    {'InstanceId': 'i-2222', 'Type': 't2.large', 'State': 'stopped'},
]

instance_map = {i['InstanceId']: i for i in instances}   # dict comprehension

print(instance_map['i-2222'])          # {'InstanceId': 'i-2222', ...}
print(instance_map['i-2222']['State']) # stopped
```
**Why it matters:** converting a list to a `dict` keyed by ID turns an O(n) search into an O(1) lookup — essential once you're dealing with hundreds of resources.

### 2. Layer config: defaults → environment → CLI overrides

**Scenario:** Your app's config comes from three sources with increasing priority: built-in defaults, environment variables, then CLI flags.

```python
defaults = {'log_level': 'info', 'timeout': 30, 'region': 'us-east-1'}
env_config = {'timeout': 60}
cli_args = {'log_level': 'debug'}

final_config = {**defaults, **env_config, **cli_args}   # later dicts win on conflict
print(final_config)
# {'log_level': 'debug', 'timeout': 60, 'region': 'us-east-1'}
```
**Why it matters:** `{**a, **b, **c}` is the standard Python idiom for config layering — the same pattern behind how most CLIs and frameworks resolve settings.

### 3. Group instances by state without KeyErrors

**Scenario:** You're building an inventory grouped by instance state (`running`, `stopped`, ...) but don't know in advance which states will appear.

```python
from collections import defaultdict

instances = [
    {'id': 'i-1', 'state': 'running'},
    {'id': 'i-2', 'state': 'stopped'},
    {'id': 'i-3', 'state': 'running'},
]

by_state = defaultdict(list)
for inst in instances:
    by_state[inst['state']].append(inst['id'])

print(dict(by_state))   # {'running': ['i-1', 'i-3'], 'stopped': ['i-2']}
```
**Why it matters:** `defaultdict(list)` avoids the boilerplate of checking `if key not in d: d[key] = []` every time — the standard way to group data by a field.

### 4. Safely pull optional fields out of a cloud API response

**Scenario:** AWS/GCP API responses often omit fields when they don't apply (e.g. no public IP on a private instance). Direct key access would crash your script.

```python
instance = {
    'InstanceId': 'i-123456',
    'InstanceType': 't2.micro',
    # 'PublicIpAddress' key is simply absent here
}

public_ip = instance.get('PublicIpAddress')            # None, no crash
private_ip = instance.get('PrivateIpAddress', '10.0.0.1')  # fallback default

print(f"Public IP: {public_ip}")     # Public IP: None
print(f"Private IP: {private_ip}")   # Private IP: 10.0.0.1

if public_ip is None:
    print("⚠️ Instance has no public IP — internal only")
```
**Why it matters:** `instance['PublicIpAddress']` would raise `KeyError` and crash the script the first time a field is missing — `.get()` with a default is the safe, real-world pattern for API responses.

### 5. Build a port-name lookup, then invert it

**Scenario:** You maintain a name→port mapping for a security group script, but a monitoring tool needs the reverse: port→name.

```python
port_map = {'ssh': 22, 'http': 80, 'https': 443}

# Convert to AWS-style tag format
aws_style = [{'Key': k, 'Value': v} for k, v in port_map.items()]
print(aws_style)

# Invert the mapping — port -> name
reverse_map = {port: name for name, port in port_map.items()}
print(reverse_map)   # {22: 'ssh', 80: 'http', 443: 'https'}
print(reverse_map[443])   # https
```
**Why it matters:** `.items()` plus a comprehension is how you reshape dict data for different consumers (a report needs `[{key, value}]`, an alert tool needs the reverse lookup).

## 🔑 Dict Basics

- Written as `{key: value, ...}`; keys must be unique and hashable (immutable), values can be anything
- Mutable, and preserves insertion order (Python 3.7+)
- Average O(1) lookup, insert, and delete

```python
instance = {
    'InstanceId': 'i-1234567890abcdef0',
    'InstanceType': 't2.micro',
    'State': 'running',
}
print(instance['InstanceType'])   # t2.micro
```

## 🏗 Creating Dictionaries

```python
tags = {}                                              # empty dict
config = dict(host='db.example.com', port=5432)        # from keyword args
ports = dict([('ssh', 22), ('http', 80)])                # from list of tuples

# dict comprehension — very common for transforming a list into a dict
instance_states = {i['id']: i['state'] for i in instances}
```

## 🔍 Accessing Values Safely

```python
instance = {'InstanceId': 'i-123', 'InstanceType': 't2.micro'}

instance_type = instance['InstanceType']          # KeyError if missing — use only when key is guaranteed
public_ip = instance.get('PublicIpAddress')        # None if missing — safe
region = instance.get('Region', 'us-east-1')        # default value if missing — safest
```

**Rule of thumb:** use `[]` only when the key is guaranteed to exist; use `.get()` for anything coming from an external API or optional config.

## ✏️ Modifying & Merging

```python
instance = {'InstanceId': 'i-123', 'State': 'running'}

instance['LaunchTime'] = '2024-01-01T12:00:00Z'      # add/update a single key
instance.update({'Platform': 'linux', 'Monitoring': True})  # update multiple keys

del instance['Platform']            # remove a key
state = instance.pop('State')        # remove and return a value
instance.clear()                      # empty the dict
```

**Merging two dicts (several equivalent ways):**

```python
defaults = {'timeout': 30, 'retries': 3}
custom = {'timeout': 60, 'region': 'us-east-1'}

merged = {**defaults, **custom}      # unpacking — custom wins on conflict
merged = defaults | custom             # same result, Python 3.9+
defaults.update(custom)                 # in-place merge, modifies defaults directly
```

## 🧰 Dict Methods Reference

| Method                | What it does                            | Example                                   |
| ----------------------- | ------------------------------------------ | ---------------------------------------------- |
| `.get(k, default)`      | safe read, no `KeyError`                    | `instance.get('SubnetId', 'default')`         |
| `.setdefault(k, default)` | get value, or set+return default if missing | `config.setdefault('region', 'us-east-1')`   |
| `.update(other)`         | merge another dict in                       | `config.update({'timeout': 30})`              |
| `.pop(k, default)`       | remove key & return its value               | `instances.pop('i-123', None)`                |
| `.popitem()`             | remove & return the last-inserted pair      | `key, val = tags.popitem()`                    |
| `.keys()` / `.values()` / `.items()` | views over keys/values/pairs   | `for k, v in config.items():`                  |
| `.copy()`                | shallow copy                                 | `backup = config.copy()`                        |
| `len(d)`                  | number of keys                               | `len(env_vars)`                                  |

⚠️ **Gotcha:** `.copy()` is *shallow* — if a value is itself a dict/list, both copies still share that nested object. Use `copy.deepcopy()` for nested structures you need fully independent.

## 📐 Dictionary Comprehension

```python
# basic transform
squares = {x: x**2 for x in range(1, 6)}

# with a filter condition
running = {id: state for id, state in instance_states.items() if state == 'running'}

# from two parallel lists
services = ['api', 'db', 'cache']
health = dict.fromkeys(services, 'unknown')   # {'api': 'unknown', 'db': 'unknown', ...}
```

## 🧬 Special Dict Types (from `collections`)

| Type          | What it's for                                                    |
| -------------- | -------------------------------------------------------------------- |
| `defaultdict`  | auto-creates a default value for missing keys (great for grouping)   |
| `OrderedDict`  | remembers insertion order and adds `.move_to_end()` (mostly legacy now that regular `dict` keeps order) |
| `ChainMap`     | layers multiple dicts for lookup without merging them (config overrides) |

```python
from collections import defaultdict, ChainMap

counts = defaultdict(int)
counts['errors'] += 1     # no KeyError, starts at 0 automatically
print(counts['errors'])   # 1

defaults = {'debug': False, 'host': 'localhost'}
overrides = {'debug': True}
config = ChainMap(overrides, defaults)   # first dict wins
print(config['debug'])   # True  (from overrides)
print(config['host'])    # localhost (fallback to defaults)
```

## ⚙️ Performance Notes

| Operation     | Complexity | Practical impact                         |
| -------------- | ------------ | ---------------------------------------------- |
| get/set/delete | O(1) average | fast config lookups and updates                |
| iteration      | O(n)         | fine for full scans, but avoid inside a hot loop|
