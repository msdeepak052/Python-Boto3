## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

Real scenarios solved end-to-end so you can see dicts used the way you'd actually use them on the job.

### 1. Turn an instance list into a fast lookup dict

**Scenario:** You get a list of instances back from a cloud API and need to look one up by ID repeatedly — a list would mean scanning every time.

```python
instances = [
    {'InstanceId': 'i-1111', 'Type': 't2.micro', 'State': 'running'},
    {'InstanceId': 'i-2222', 'Type': 't2.large', 'State': 'stopped'},
]

instance_map = {i['InstanceId']: i for i in instances}   # dict comprehension

print(instance_map['i-2222'])          # {'InstanceId': 'i-2222', ...}
print(instance_map['i-2222']['State']) # stopped
```
**Why it matters:** converting a list to a `dict` keyed by ID turns an O(n) search into an O(1) lookup — essential once you're dealing with hundreds of resources.

### 2. Layer config: defaults → environment → CLI overrides

**Scenario:** Your app's config comes from three sources with increasing priority: built-in defaults, environment variables, then CLI flags.

```python
defaults = {'log_level': 'info', 'timeout': 30, 'region': 'us-east-1'}
env_config = {'timeout': 60}
cli_args = {'log_level': 'debug'}

final_config = {**defaults, **env_config, **cli_args}   # later dicts win on conflict
print(final_config)
# {'log_level': 'debug', 'timeout': 60, 'region': 'us-east-1'}
```
**Why it matters:** `{**a, **b, **c}` is the standard Python idiom for config layering — the same pattern behind how most CLIs and frameworks resolve settings.

---

### 3. Group instances by state without KeyErrors

**Scenario:** You're building an inventory grouped by instance state (`running`, `stopped`, ...) but don't know in advance which states will appear.

```python
from collections import defaultdict

instances = [
    {'id': 'i-1', 'state': 'running'},
    {'id': 'i-2', 'state': 'stopped'},
    {'id': 'i-3', 'state': 'running'},
]

by_state = defaultdict(list)
for inst in instances:
    by_state[inst['state']].append(inst['id'])

print(dict(by_state))   # {'running': ['i-1', 'i-3'], 'stopped': ['i-2']}
```
**Why it matters:** `defaultdict(list)` avoids the boilerplate of checking `if key not in d: d[key] = []` every time — the standard way to group data by a field.

### 4. Safely pull optional fields out of a cloud API response

**Scenario:** AWS/GCP API responses often omit fields when they don't apply (e.g. no public IP on a private instance). Direct key access would crash your script.

```python
instance = {
    'InstanceId': 'i-123456',
    'InstanceType': 't2.micro',
    # 'PublicIpAddress' key is simply absent here
}

public_ip = instance.get('PublicIpAddress')            # None, no crash
private_ip = instance.get('PrivateIpAddress', '10.0.0.1')  # fallback default

print(f"Public IP: {public_ip}")     # Public IP: None
print(f"Private IP: {private_ip}")   # Private IP: 10.0.0.1

if public_ip is None:
    print("⚠️ Instance has no public IP — internal only")
```
**Why it matters:** `instance['PublicIpAddress']` would raise `KeyError` and crash the script the first time a field is missing — `.get()` with a default is the safe, real-world pattern for API responses.

---

### 5. Build a port-name lookup, then invert it

**Scenario:** You maintain a name→port mapping for a security group script, but a monitoring tool needs the reverse: port→name.

```python
port_map = {'ssh': 22, 'http': 80, 'https': 443}

# Convert to AWS-style tag format
aws_style = [{'Key': k, 'Value': v} for k, v in port_map.items()]
print(aws_style)

# Invert the mapping — port -> name
reverse_map = {port: name for name, port in port_map.items()}
print(reverse_map)   # {22: 'ssh', 80: 'http', 443: 'https'}
print(reverse_map[443])   # https
```
**Why it matters:** `.items()` plus a comprehension is how you reshape dict data for different consumers (a report needs `[{key, value}]`, an alert tool needs the reverse lookup).

## **1. Dictionary Fundamentals**

### **What is a Dictionary?**
An unordered, mutable collection of key-value pairs with O(1) average case lookup time.

```python
# Examples:
book = {
    'ISBN': '978-0-13-468599-1',
    'Format': 'Hardcover',
    'Status': 'checked_out',
    'ShelfLocation': 'Fiction-A3'
}

library_card = {
    'CardId': 'LC-48213',
    'CardType': 'Standard Membership',
    'BorrowingRules': [
        {'MaxBooks': 5, 'LoanDays': 14, 'LateFeePerDay': 0.25}
    ]
}

print("Format:", book['Format'])
print("--------------------------------------------")
print("Data Type of library_card['BorrowingRules'] :",type(library_card['BorrowingRules'])," and Value is :",library_card['BorrowingRules'])
print("--------------------------------------------")
print("Data Type of library_card['BorrowingRules'][0]",type(library_card['BorrowingRules'][0])," and Value is :",library_card['BorrowingRules'][0])
print("--------------------------------------------")
```

### **Key Characteristics**
- **Key-Value Pairs**: Uniquely mapped relationships
- **Mutable**: Can modify after creation
- **Unordered**: No guaranteed order (Python 3.7+ preserves insertion order)
- **Fast Lookups**: O(1) average time complexity
- **Heterogeneous**: Can mix data types for keys/values

### **`OrderedDict` (from collections)**

#### 📌 What is `OrderedDict`?

`OrderedDict` is a dictionary subclass from `collections` that **remembers the order** in which keys were inserted.

✅ Useful when:

* You need predictable key order.
* You're working with older Python versions (**<3.7**) where regular `dict` didn't maintain insertion order.

---

> ⚠️ **Note:** From **Python 3.7+**, the built-in `dict` **preserves insertion order**, so `OrderedDict` is less necessary — but it still has some **extra features** (e.g. `move_to_end()`).

---

### ✅ Basic Example

```python
from collections import OrderedDict

# Creating an OrderedDict
checkouts = OrderedDict()
checkouts['fiction'] = 3
checkouts['mystery'] = 5
checkouts['romance'] = 2

# Print the OrderedDict
print(checkouts)
```

#### 🖨️ Output:

```
OrderedDict([('fiction', 3), ('mystery', 5), ('romance', 2)])
```

---

### ✅ Preserves Insertion Order

```python
for genre, count in checkouts.items():
    print(f"{genre}: {count}")
```

#### 🖨️ Output:

```
fiction: 3
mystery: 5
romance: 2
```

---

### 🔄 Reordering with `move_to_end()`

```python
checkouts.move_to_end('mystery')   # Moves 'mystery' to end
print(checkouts)
```

#### 🖨️ Output:

```
OrderedDict([('fiction', 3), ('romance', 2), ('mystery', 5)])
```

Use `move_to_end('mystery', last=False)` to move it to the **beginning**.

---

### ✅ Comparing `dict` vs `OrderedDict`

```python
from collections import OrderedDict

d1 = {'fiction': 3, 'mystery': 5, 'romance': 2}
d2 = OrderedDict({'fiction': 3, 'mystery': 5, 'romance': 2})

print(d1 == d2)  # ✅ True (same content)
```

But:

```python
d3 = OrderedDict({'mystery': 5, 'fiction': 3})
print(d2 == d3)  # ❌ False (order matters in OrderedDict)
```

### **`ChainMap` (from collections)**


### 🔗 What is `ChainMap`?

`ChainMap` (from the `collections` module) is a **dict-like class** that groups **multiple dictionaries** into a single, viewable unit.

* It **searches keys in order** — from first to last dictionary.
* It doesn’t merge them — it just **links them logically**.
* ✅ You can use it to simulate **nested scopes**, override configs, or combine multiple sources.

---

### ✅ Syntax

```python
from collections import ChainMap

ChainMap(dict1, dict2, dict3, ...)
```

---

### ✅ Real Example: Settings with Defaults

```python
from collections import ChainMap

# Default settings
defaults = {
    'branch': 'central',
    'notifications': False,
    'catalog_host': 'localhost'
}

# User override settings
user_config = {
    'notifications': True,
    'catalog_host': '0.0.0.0'
}

# Combine using ChainMap
config = ChainMap(user_config, defaults)

# Access values
print(config['branch'])         # 'central'    (from defaults)
print(config['notifications'])  # True         (overridden by user_config)
print(config['catalog_host'])   # '0.0.0.0'    (overridden)
```


- In the `ChainMap`, **the first dictionary passed** takes **highest precedence**. So in this example:

```python
from collections import ChainMap

defaults = {
    'branch': 'central',
    'notifications': False,
    'catalog_host': 'localhost'
}

user_config = {
    'notifications': True,
    'catalog_host': '0.0.0.0'
}

config = ChainMap(user_config, defaults)
```

---

### ✅ Precedence Order (Top to Bottom):

```
config = ChainMap(user_config, defaults)
                   ↑             ↑
          1st (higher priority)   2nd (fallback)
```

---

### 🔍 Answering Your Question:

```python
print(config['notifications'])  # ✅ Comes from user_config → True
print(config['catalog_host'])   # ✅ Comes from user_config → '0.0.0.0'
print(config['branch'])         # ✅ Not in user_config → fallback to defaults → 'central'
```

---

### ✅ So:

| Key     | Value       | Source        |
| ------- | ----------- | -------------- |
| `notifications` | `True`      | `user_config` |
| `catalog_host`  | `'0.0.0.0'` | `user_config` |
| `branch`   | `'central'`     | `defaults`    |

```python
def merge_configs(base, override):
    """Deep merge two configuration dictionaries"""
    merged = base.copy()
    for key, value in override.items():
        if (key in merged and isinstance(merged[key], dict)
                and isinstance(value, dict)):
```

## **9. Advanced Dictionary Techniques**

### **Dictionary Unpacking (Python 3.5+)**
```python
# Merge dictionaries
defaults = {'loan_days': 14, 'reminders': 2}
custom = {'loan_days': 21, 'branch': 'central'}
combined = {**defaults, **custom}  # {'loan_days': 21, 'reminders': 2, 'branch': 'central'}

# Function argument unpacking
def register_book(**kwargs):
    # kwargs becomes dictionary
    catalog.add_book(**kwargs)
```

> We're looking at a **dictionary merge** using the `**` (unpacking operator), which is a concise and Pythonic way to combine multiple dictionaries.

---

### 🔧 The Code

```python
defaults = {'loan_days': 14, 'reminders': 2}
custom = {'loan_days': 21, 'branch': 'central'}

combined = {**defaults, **custom}
```

---

### 🔍 How It Works

* `**defaults` unpacks all key-value pairs from `defaults`
* `**custom` unpacks all key-value pairs from `custom`
* If there are **duplicate keys**, the **last one wins**

---

### ✅ Final `combined` Dictionary:

```python
{
    'loan_days': 21,       # overridden by custom
    'reminders': 2,        # only in defaults
    'branch': 'central'    # only in custom
}
```

---

### 🧠 Why is `loan_days = 21` and not `14`?

Because of the **merge order**:

```python
combined = {**defaults, **custom}
```

* First, `loan_days: 14` is added from `defaults`
* Then, `loan_days: 21` from `custom` **overwrites** the previous value
* So `loan_days` becomes `21`

---

### 🔁 Reverse the order → Different result:

```python
combined = {**custom, **defaults}
# loan_days = 14 (from defaults)
```

---

### ✅ Use Case: Config override pattern

```python
# Base/default config
defaults = {'branch': 'central', 'loan_days': 14}

# User override
user = {'loan_days': 7}

config = {**defaults, **user}
# user config takes precedence
```

---

### 📌 Summary

| Merge Order              | Final Value of `loan_days` |
| -------------------------- | --------------------------- |
| `{**defaults, **custom}` | `21` (from `custom`)     |
| `{**custom, **defaults}` | `14` (from `defaults`)   |

## **10. Best Practices**

1. **Use `.get()` for safe access** to avoid KeyError
2. **Prefer dict comprehension** for transformations
3. **Use `defaultdict`** for grouping operations
4. **Leverage `TypedDict`** for complex records
5. **Document dictionary structures** when they represent schemas
6. **Validate input dictionaries** in application handlers
7. **Consider memory overhead** for very large dictionaries
8. **Use `json.dumps()`** for logging dictionaries

# **Dictionary Built-in Methods in Python: Comprehensive Guide**

Dictionaries are the backbone of everyday Python programming, used for everything from record-keeping to configuration handling. This guide explores all dictionary built-in methods with practical, easy-to-follow examples.

## **1. Core Dictionary Methods**

### **`.get(key[, default])` - Safe Value Access**
Retrieves a value without raising KeyError if the key doesn't exist.

```python
book = {
    'ISBN': '978-0-13-468599-1',
    'Format': 'Hardcover',
    'Status': {'Name': 'checked_out'}
}

# Safe access to nested data
due_date = book.get('DueDate')  # Returns None if missing
shelf = book.get('Location', {}).get('ShelfCode', 'A1-General')

# With default value
reminder = book.get('Reminder', {'State': 'disabled'})
```

**Use Case:** Safely processing library records where fields may be absent.

### **`.setdefault(key[, default])` - Get or Set Default**
Returns the value if key exists, otherwise sets the key to default and returns it.

```python
settings = {'loan_days': 14, 'reminders': 3}

# Existing key
print(settings.setdefault('loan_days', 21))  # Output: 14

# New key
branch = settings.setdefault('branch', 'central')
print(settings)  # {'loan_days': 14, 'reminders': 3, 'branch': 'central'}
```

**Example:** Initializing new book records:

```python
def init_book_record(isbn):
    record = {'ISBN': isbn}
    record.setdefault('Labels', []).append({'Key': 'AddedBy', 'Value': 'Librarian'})
    return record
```

## **2. Dictionary Update Methods**

Updates dictionary with key/value pairs from another dictionary or iterable.


**Use Case:** Merging settings layers:

## **3. Dictionary Removal Methods**

### **`.pop(key[, default])` - Remove by Key**
Removes and returns the value for the key. Returns default if key not found.

```python
loans = {
    '978-0-13-468599-1': 'checked_out',
    '978-1-40-289364-2': 'returned',
    '978-0-59-652068-7': 'checked_out'
}

# Remove and get status
status = loans.pop('978-1-40-289364-2')  # 'returned'

# With default
status = loans.pop('978-9-99-999999-9', 'not_found')  # 'not_found'
```

**Example:** Processing a book-return queue:


### **`.popitem()` - Remove Last Item (Python 3.7+)**
Removes and returns (key, value) pair in LIFO order.

### **`.clear()` - Remove All Items**
Empties the dictionary.

```python
temp_holds = {'hold-1': 'fiction', 'hold-2': 'reference'}
```

## **6. Special Dictionary Methods**

### **`dict.fromkeys(iterable[, value])` - Create from Keys**
Creates a new dictionary with keys from an iterable and a fixed value.

```python
def chunks(lst, n):
    """Yield successive n-sized chunks from list"""
    for i in range(0, len(lst), n):
        yield lst[i:i + n]
```

### ✅ 1. **Using `|` Operator (Python 3.9+)**

```python
dict1 = {'a': 1, 'b': 2}
dict2 = {'b': 3, 'c': 4}

merged = dict1 | dict2
print(merged)
```

#### 🖨️ Output:

```python
{'a': 1, 'b': 3, 'c': 4}
```

* `dict2` values **override** values from `dict1` on duplicate keys.

---

### ✅ 2. **Using `{**dict1, **dict2}` (All Python 3.x)**

```python
dict1 = {'x': 10, 'y': 20}
dict2 = {'y': 30, 'z': 40}

merged = {**dict1, **dict2}
print(merged)
```

#### 🖨️ Output:

```python
{'x': 10, 'y': 30, 'z': 40}
```

* Same behavior: `dict2` overrides `dict1` if keys overlap.

---

### ✅ 3. **Using `.update()` (in-place merge)**

```python
dict1 = {'name': 'Deepak'}
dict2 = {'role': 'Librarian', 'name': 'D Yadav'}

dict1.update(dict2)
print(dict1)
```

#### 🖨️ Output:

```python
{'name': 'D Yadav', 'role': 'Librarian'}
```

* `dict1` is **modified** directly.
* No new dictionary is created.

---

### ✅ 4. **Using `collections.ChainMap` (No merging, just chaining)**

```python
from collections import ChainMap

dict1 = {'a': 1}
dict2 = {'a': 2, 'b': 3}

combined = ChainMap(dict2, dict1)
print(combined['a'])  # 2 (from dict2)
print(combined['b'])  # 3
```
