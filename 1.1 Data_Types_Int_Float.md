## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

Real scenarios solved end-to-end so you can see `int`/`float` used the way you'd actually use them on the job.

### 1. Autoscaling decision from a CPU metric

**Scenario:** Your monitoring system reports CPU usage as a string (from a JSON metrics API). You need to decide whether to scale up.

```python
cpu_util_raw = "87.6"          # comes in as a string from the metrics API
threshold = 80.0

cpu_util = float(cpu_util_raw)  # str -> float, required before comparing numerically

if cpu_util > threshold:
    print(f"🔺 Scale up: CPU at {cpu_util}% (threshold {threshold}%)")
else:
    print(f"✅ CPU normal: {cpu_util}%")
```
**Why it matters:** metrics APIs and env vars always hand you strings — forgetting to convert before comparing is a common real bug (`"87.6" > 80.0` would error).

### 2. Total monthly cloud cost across services

**Scenario:** You pull per-service costs from a billing API and need a rounded total for a Slack cost report.

```python
service_costs = [412.567, 98.10, 1250.899, 76.25]   # list of float, one per service

total_cost = sum(service_costs)
print(f"Raw total: {total_cost}")            # Raw total: 1837.816
print(f"Monthly cost: ${round(total_cost, 2)}")  # Monthly cost: $1837.82

most_expensive = max(service_costs)
print(f"Most expensive service costs: ${round(most_expensive, 2)}")
```
**Why it matters:** `sum()` + `round()` is the standard combo for any cost or usage report — never print raw floats to humans.

### 3. Capacity planning — how many nodes do you need?

**Scenario:** You need to schedule 130 pods, and each node fits 12 pods. You want the number of *full* nodes and how many pods are left over (needing one more, partially-filled node).

```python
total_pods = 130
pods_per_node = 12

full_nodes = total_pods // pods_per_node   # floor division -> 10
leftover_pods = total_pods % pods_per_node  # modulo -> 10

nodes_needed = full_nodes + (1 if leftover_pods > 0 else 0)

print(f"Full nodes: {full_nodes}")          # 10
print(f"Leftover pods: {leftover_pods}")    # 10
print(f"Total nodes to provision: {nodes_needed}")  # 11
```
**Why it matters:** `//` and `%` show up anywhere you're bin-packing workloads onto fixed-capacity nodes — a real capacity-planning calculation, not a textbook one.

### 4. Exponential backoff for retrying a failed API/deploy call

**Scenario:** A deploy step calls an API that sometimes fails. You retry with exponential backoff (1s, 2s, 4s, 8s...) capped at a max wait.

```python
base_delay = 1        # seconds
max_delay = 30
attempt = 4            # this is the 4th retry

delay = pow(2, attempt - 1) * base_delay   # 2^(attempt-1) * base
delay = min(delay, max_delay)               # never wait longer than max_delay

print(f"Retry attempt {attempt}: waiting {delay}s")  # Retry attempt 4: waiting 8s

attempt = 6
delay = min(pow(2, attempt - 1) * base_delay, max_delay)
print(f"Retry attempt {attempt}: waiting {delay}s")  # capped -> waiting 30s
```
**Why it matters:** `pow()` and `min()` together are exactly how retry/backoff logic is written in real deployment scripts, health checks, and API clients.

### 5. Validate and normalize instance-count input from a CLI/config

**Scenario:** A user passes `--instances` as a string via CLI or Terraform variable. You must validate it's a usable, positive whole number before provisioning.

```python
instance_str = "5"

instances = int(instance_str)      # str -> int

if instances > 0:
    print(f"Provisioning {instances} instance(s)")
else:
    print("🔴 Invalid instance count — must be positive")

# Guard against accidental float-like strings breaking int()
raw_input = "5.0"
try:
    instances = int(raw_input)
except ValueError:
    instances = int(float(raw_input))   # fallback: go through float first
print(instances, type(instances))   # 5 <class 'int'>
```
**Why it matters:** `int("5.0")` actually raises `ValueError` in Python — a real gotcha when parsing user/CLI input that platform engineers hit often.

## 🔢 `int` and `float` Basics

- `int` → whole numbers, no decimal point
- `float` → numbers with a decimal point, used for percentages, costs, measurements
- Both support `type()` to check what you're working with

```python
cpu_cores = 4              # int
cpu_utilization = 78.5     # float

print(type(cpu_cores))         # <class 'int'>
print(type(cpu_utilization))   # <class 'float'>
```

## 🔄 Type Conversion

- `int(x)` and `float(x)` convert strings (or other numbers) into that type
- Needed constantly because CLI args, env vars, JSON/API responses, and file contents are always strings

```python
instance_count = int("5")     # '5' -> 5
price = float("42.75")        # '42.75' -> 42.75

print(instance_count, type(instance_count))   # 5 <class 'int'>
print(price, type(price))                     # 42.75 <class 'float'>
```

⚠️ **Gotcha:** `int("5.0")` raises `ValueError` — a string that *looks* like a float must go through `float()` first, then `int()` if you need a whole number.

## ➕ Arithmetic Operations

| Operator | Meaning         | Example (`a=10, b=3`) | Result  |
| -------- | ---------------- | ----------------------- | -------- |
| `+`      | add               | `a + b`                 | `13`     |
| `-`      | subtract          | `a - b`                 | `7`      |
| `*`      | multiply          | `a * b`                 | `30`     |
| `/`      | divide (float)    | `a / b`                 | `3.333…` |
| `//`     | floor divide      | `a // b`                 | `3`      |
| `%`      | modulo (remainder)| `a % b`                  | `1`      |
| `**`     | exponent          | `a ** b`                 | `1000`   |

**Real use:** resource allocation (`//`, `%`), percentages, threshold checks, backoff delays (`**`).

## 🧰 Useful Built-in Functions

| Function            | What it does                     | Example                        |
| -------------------- | ---------------------------------- | --------------------------------- |
| `abs(x)`             | absolute value                     | `abs(-20)` → `20`                |
| `round(x, n)`        | round to `n` decimal places        | `round(3.1415, 2)` → `3.14`      |
| `pow(x, y)`          | x to the power y (same as `**`)    | `pow(2, 4)` → `16`               |
| `max(list)` / `min(list)` | largest / smallest in a list  | `max([23, 17, 89])` → `89`       |
| `sum(list)`          | add all values in a list           | `sum([20.5, 30.0, 49.5])` → `100.0` |
| `float.is_integer()` | is this float a whole number?      | `(5.0).is_integer()` → `True`    |

```python
values = [23, 17, 89, 45]
print(max(values))   # 89 — e.g. peak CPU/memory across nodes
print(min(values))   # 17 — e.g. lowest available disk space

usage = [20.5, 30.0, 49.5]
print(sum(usage))    # 100.0 — e.g. total memory used across pods

print(round(12.9765, 2))   # 12.98 — clean up a cost/metric before display
print((5.0).is_integer())  # True — useful to check if a float is "clean"
```
