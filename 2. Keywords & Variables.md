## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Validating Terraform Variable Names Before `terraform apply`

**Scenario:** Before running `terraform apply`, a platform engineer wants to validate that every variable name in a parsed `terraform.tfvars`-style dict is a legal identifier and doesn't collide with a reserved keyword, catching typos before they reach the CI pipeline.

```python
import keyword

# Variable names pulled from a parsed terraform.tfvars file
tfvars = {
    "region": "us-east-1",
    "instance_count": 3,
    "class": "t3.micro",      # bad: 'class' is a reserved keyword
    "2fa_enabled": True,      # bad: starts with a digit
}

def validate_names(vars_dict):
    valid = []
    invalid = []
    for name in vars_dict:
        # A name must be a legal identifier AND not a reserved keyword
        if name.isidentifier() and not keyword.iskeyword(name):
            valid.append(name)
        else:
            invalid.append(name)
    return valid, invalid

valid_names, invalid_names = validate_names(tfvars)
print("Valid:", valid_names)     # Valid: ['region', 'instance_count']
print("Invalid:", invalid_names) # Invalid: ['class', '2fa_enabled']
```

**Why it matters:** Terraform and Python share the same identifier rules, so a quick `isidentifier()` + `iskeyword()` sweep over a parsed variables file catches naming mistakes in a pre-apply linting step, long before `terraform apply` fails mid-deployment.

### 2. Unpacking `kubectl get pods` Status Lines with Multiple Assignment

**Scenario:** A script tails `kubectl get pods -o wide` output and needs to unpack each line into named variables in one step, then use a `global` counter to track how many pods across the whole cluster are not yet ready.

```python
unready_count = 0  # global counter shared across calls

def check_pod(line):
    global unready_count
    # Multiple assignment: unpack a status line in one line
    name, ready, status, restarts, age = line.split()
    is_ready = ready.split("/")[0] == ready.split("/")[1]
    if not is_ready:
        unready_count += 1
    print(f"{name}: ready={is_ready}, status={status}")

pod_lines = [
    "web-7d9f 1/1 Running 0 2d",
    "worker-2a1c 0/1 CrashLoopBackOff 5 10m",
    "cache-88bd 1/1 Running 0 5d",
]

for line in pod_lines:
    check_pod(line)

print("Pods not ready:", unready_count)  # Pods not ready: 1
```

**Why it matters:** Multiple assignment turns whitespace-separated `kubectl` output into readable, named variables in a single line, and `global` lets a small health-check function update a shared cluster-wide counter without threading state through every call.

### 3. Pipeline Constants and Optional Config with `None`

**Scenario:** A CI/CD pipeline script defines its tunable constants (retry count, timeout) in `UPPER_CASE` and treats an optional Slack webhook as `None` when the team hasn't configured one, skipping the notification step gracefully instead of crashing.

```python
# Constants (by convention, never reassigned during the run)
MAX_RETRIES = 3
TIMEOUT_SECONDS = 90

# Optional setting - None means "not configured"
SLACK_WEBHOOK_URL = None

def notify_slack(message):
    if SLACK_WEBHOOK_URL is None:
        print("Slack webhook not set, skipping notification")
        return
    print(f"Sending to Slack: {message}")

def run_pipeline():
    attempt = 1
    succeeded = False
    while attempt <= MAX_RETRIES and not succeeded:
        print(f"Attempt {attempt} of {MAX_RETRIES} (timeout={TIMEOUT_SECONDS}s)")
        succeeded = attempt == 2  # simulate success on 2nd try
        attempt += 1
    notify_slack("Pipeline succeeded" if succeeded else "Pipeline failed")

run_pipeline()
# Output:
# Attempt 1 of 3 (timeout=90s)
# Attempt 2 of 3 (timeout=90s)
# Slack webhook not set, skipping notification
```

**Why it matters:** Naming true constants in `UPPER_CASE` signals "don't change me at runtime," and using `None` as an explicit "not configured" sentinel (checked with `is None`, not `== None`) lets optional integrations degrade gracefully instead of throwing errors in a pipeline.

### 4. Health-Checking a Cloud API Response

**Scenario:** A script polls a cloud provider's instance-status API and must decide if an instance is truly healthy, combining several boolean keywords and gracefully handling a response that's missing a field.

```python
responses = [
    {"state": "running", "checks_passed": True, "az": "us-east-1a"},
    {"state": "running", "checks_passed": False, "az": "us-east-1b"},
    {"state": "stopped"},  # missing 'checks_passed' key entirely
]

def is_healthy(instance):
    try:
        state = instance["state"]
        passed = instance["checks_passed"]
    except KeyError:
        return False  # incomplete data counts as unhealthy
    # and / or / in / is all combine into one readability check
    return state == "running" and passed is True and "us-east-1" in instance.get("az", "")

for resp in responses:
    print(is_healthy(resp))
# Output:
# True
# False
# False
```

**Why it matters:** Real API responses are never fully trustworthy — combining `and`, `or`, `in`, and `is` gives precise, readable health-check logic, while `try`/`except KeyError` stops a single malformed response from crashing a monitoring loop.

### 5. Parsing a `.env` File for a Deployment

**Scenario:** Before a deployment starts, a script reads a `.env` file, skips blank lines and comments, unpacks each `KEY=value` line with multiple assignment, and confirms the required keys are present before continuing.

```python
env_lines = [
    "# Deployment environment file",
    "DEPLOY_ENV=production",
    "",
    "REPLICAS=4",
    "REGION=eu-west-1",
]

config = {}
for line in env_lines:
    line = line.strip()
    if not line or line.startswith("#"):
        continue  # skip blanks and comments
    key, value = line.split("=", 1)  # multiple assignment from split
    config[key] = value

required = ["DEPLOY_ENV", "REPLICAS", "REGION"]
missing = [key for key in required if key not in config]

if missing:
    print("Missing required keys:", missing)
else:
    print("Config loaded:", config)
# Output:
# Config loaded: {'DEPLOY_ENV': 'production', 'REPLICAS': '4', 'REGION': 'eu-west-1'}
```

**Why it matters:** `continue` keeps the parser from choking on comments and blank lines, multiple assignment turns each `KEY=value` line into two clean variables in one step, and an `in`-based check against a required-keys list catches a missing setting before it causes a failed deployment.

## 🧠 What Are Keywords in Python?

* **Keywords** are **reserved words** that **cannot be used as variable names**.
* They define **Python syntax and structure**.
* Python has **35+ keywords** as of Python 3.10+.

You can check them via:

```python
import keyword
print(keyword.kwlist)
```

- Here are some important Python keywords:

1. **and**: It is a logical operator that returns `True` if both operands are true.

2. **or**: It is a logical operator that returns `True` if at least one of the operands is true.

3. **not**: It is a logical operator that returns the opposite of the operand's truth value.

4. **if**: It is used to start a conditional statement and is followed by a condition that determines whether the code block is executed.

5. **else**: It is used in conjunction with `if` to define an alternative code block to execute when the `if` condition is `False`.

6. **elif**: Short for "else if," it is used to check additional conditions after an `if` statement and is used in combination with `if` and `else`.

7. **while**: It is used to create a loop that repeatedly executes a block of code as long as a specified condition is true.

8. **for**: It is used to create a loop that iterates over a sequence (such as a list, tuple, or string) and executes a block of code for each item in the sequence.

9. **in**: Used with `for`, it checks if a value is present in a sequence.

10. **try**: It is the beginning of a block of code that is subject to exception handling. It is followed by `except` to catch and handle exceptions.

11. **except**: Used with `try`, it defines a block of code to execute when an exception is raised in the corresponding `try` block.

12. **finally**: Used with `try`, it defines a block of code that is always executed, whether an exception is raised or not.

13. **def**: It is used to define a function in Python.

14. **return**: It is used within a function to specify the value that the function should return.

15. **class**: It is used to define a class, which is a blueprint for creating objects in object-oriented programming.

16. **import**: It is used to import modules or libraries to access their functions, classes, or variables.

17. **from**: Used with `import` to specify which specific components from a module should be imported.

18. **as**: Used with `import` to create an alias for a module, making it easier to reference in the code.

19. **True**: It represents a boolean value for "true."

20. **False**: It represents a boolean value for "false."

21. **None**: It represents a special null value or absence of value.

22. **is**: It is used for identity comparison, checking if two variables refer to the same object in memory.

23. **lambda**: It is used to create small, anonymous functions (lambda functions).

24. **with**: It is used for context management, ensuring that certain operations are performed before and after a block of code.

25. **global**: It is used to declare a global variable within a function's scope.

26. **nonlocal**: It is used to declare a variable as nonlocal, which allows modifying a variable in an enclosing (but non-global) scope.

# **Python Variables**

## 🧠 What Are Variables in Python?

Variables are **named containers** used to **store data**. You can use them to represent:

* Recipe names
* Oven temperatures
* Ingredient quantities
* Customer order IDs
* Any kind of data your script processes

---

## 🛠️ Syntax

```python
variable_name = value
```

### ✅ Examples:

```python
recipe_id = "rcp-0123456789"
flour_grams = 72.5
is_baking = True
```

---

## 🎯 Key Characteristics

| Feature            | Detail                                                                             |
| ------------------- | ------------------------------------------------------------------------------------ |
| **Dynamic Typing** | You don’t need to declare data type explicitly.                                    |
| **Case-sensitive** | `AppName` ≠ `appname`                                                              |
| **No keywords**    | You can't use Python reserved keywords (like `for`, `def`, `if`) as variable names |

---

## 🔤 Variable Naming Rules

✅ Valid:

```python
my_recipe = "rcp-001"
flour_percent = 89
```

❌ Invalid:

```python
2loaves = "my-bread"     # can't start with digit
if = 5                   # 'if' is a keyword
my-recipe = 100           # hyphens not allowed
```

---

## 🗂️ Types of Variables

### 1. **Global Variables**

Accessible throughout the program.

```python
bakery_name = "Sunrise Bakery"

def show_bakery_name():
    print(bakery_name)

show_bakery_name()  # Sunrise Bakery
```

---

### 2. **Local Variables**

Declared inside functions and used within them only.

```python
def prepare_recipe():
    ingredient = "flour"
    print(ingredient)

prepare_recipe()
# print(ingredient)  # ❌ Error: not defined globally
```

---

### 3. **Constants (by convention)**

Variables you **don’t intend to change** (not enforced).

```python
SHOP_NAME = "Sunrise Bakery"
```

---

## 🔄 Dynamic Typing

You can assign different types to the same variable:

```python
x = 5
print(type(x))   # int

x = "five"
print(type(x))   # str
```

## ✅ Python Variable Naming Rules

| Rule                                                    | Example                      |
| --------------------------------------------------------- | ------------------------------- |
| Must start with a letter or `_` (underscore)            | ✅ `batch_name`, `_token`       |
| Cannot start with a digit                               | ❌ `2loaves`                  |
| Can contain letters, numbers, and underscores           | ✅ `oven_log_2023`            |
| Cannot use Python keywords (`if`, `for`, `class`, etc.) | ❌ `if = 1`                   |
| Case-sensitive (`shift` ≠ `SHIFT`)                          | ✅ `shift`, `SHIFT` are different |

---

## 🧠 Naming Conventions in Python

Python follows **PEP 8** (Python Enhancement Proposal) guidelines:

### 🐍 1. **snake\_case** for variables and functions ✅ (preferred)

```python
recipe_id = "rcp-1234"
ingredient_dir = "/pantry/flour"
```

### 🧱 2. **UPPER\_CASE** for constants

```python
DEFAULT_OVEN_TEMP = 375
MAX_BATCHES = 3
```

### 🏗️ 3. **CamelCase** for class names

```python
class BreadRecipe:
    pass
```

---

## 💼 Naming Recommendations

| Purpose         | Convention   | Example                        |
| ----------------- | -------------- | --------------------------------- |
| Shift     | `snake_case` | `current_shift = "morning"`         |
| Ingredient Path       | `snake_case` | `ingredient_path = "/pantry/flour"`       |
| Constants       | `UPPER_CASE` | `DEFAULT_OVEN_TEMP = 375` |
| Recipe Labels | `snake_case` | `recipe_type = "sourdough"`   |
| Class Names     | `CamelCase`  | `class BreadRecipe:`     |

---

## 🔥 Common Mistakes

| Mistake                                  | Correction            |
| ------------------------------------------- | ------------------------ |
| `my-var = "x"` ❌ (hyphen not allowed)    | `my_var = "x"` ✅      |
| `2loaves = "abc"` ❌                    | `loaves2 = "abc"` ✅ |
| `for = "loop"` ❌                         | `loop_for = "loop"` ✅ |
| `MyVariable` (camelCase for variables) ❌ | `my_variable` ✅       |

