## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Parsing a Deployment Log File Line by Line

**Scenario:** A CI/CD pipeline writes every step of a deployment to `deploy.log`, and you need to scan it for `ERROR` lines without loading the whole file into memory (it can grow to hundreds of MB on a bad day).

```python
error_count = 0
error_lines = []

# Iterating line-by-line keeps memory usage flat, even for huge log files
with open('deploy.log', 'r') as f:
    for line in f:
        if 'ERROR' in line:
            error_count += 1
            error_lines.append(line.strip())

print(f"Found {error_count} error(s) in deploy.log")
for line in error_lines:
    print(f" - {line}")

# Output (example):
# Found 2 error(s) in deploy.log
#  - ERROR: image pull failed for web-service:1.4.2
#  - ERROR: readiness probe timeout on pod web-service-7d9f
```

**Why it matters:** Deployment logs can be huge, and pipelines often need to fail fast on errors — reading line-by-line lets you scan gigabyte-scale logs without exhausting memory or slowing down the CI runner.

### 2. Writing a Deployment Report to a File

**Scenario:** After a Kubernetes rollout finishes, you want to generate a short, human-readable report summarizing what was deployed, and save it to disk so it can be attached to the release ticket.

```python
from datetime import datetime

deployment = {
    'service': 'payments-api',
    'version': 'v2.3.1',
    'cluster': 'prod-us-east',
    'replicas': 6,
    'status': 'SUCCESS',
}

report = f"""Deployment Report
==================
Timestamp : {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}
Service   : {deployment['service']}
Version   : {deployment['version']}
Cluster   : {deployment['cluster']}
Replicas  : {deployment['replicas']}
Status    : {deployment['status']}
"""

# 'w' mode creates the file if missing and overwrites it if it already exists
with open('deployment_report.txt', 'w') as f:
    f.write(report)

print("Report written to deployment_report.txt")
# Output: Report written to deployment_report.txt
```

**Why it matters:** Writing a clean summary file after every rollout gives teams an auditable, shareable artifact of what changed, without them having to dig through raw pipeline logs.

### 3. Appending to an Audit Log

**Scenario:** Every time an engineer runs a privileged `kubectl` or `terraform apply` command, a shared audit log needs a new timestamped entry — without ever erasing the entries already recorded.

```python
from datetime import datetime

def record_audit_event(user, action):
    timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
    entry = f"[{timestamp}] user={user} action={action}\n"
    # 'a' mode appends to the end of the file instead of truncating it
    with open('audit.log', 'a') as f:
        f.write(entry)

record_audit_event('deepak', 'terraform apply on prod-network')
record_audit_event('deepak', 'kubectl scale deployment web --replicas=10')

# audit.log now contains (appended, not overwritten):
# [2026-08-14 09:12:03] user=deepak action=terraform apply on prod-network
# [2026-08-14 09:12:04] user=deepak action=kubectl scale deployment web --replicas=10
```

**Why it matters:** Audit trails exist to prove who did what and when — append mode guarantees history is preserved even across thousands of pipeline runs and engineer sessions.

### 4. Reading a Config File Safely with Error Handling

**Scenario:** A service reads its startup configuration from `service_config.json`, but the file might be missing, empty, or malformed after a bad deploy — the service should fall back to safe defaults instead of crashing.

```python
import json

DEFAULT_CONFIG = {'timeout': 30, 'retries': 3, 'log_level': 'INFO'}

def load_config(path):
    try:
        with open(path, 'r') as f:
            return json.load(f)
    except FileNotFoundError:
        print(f"Config file '{path}' not found — using defaults")
        return DEFAULT_CONFIG
    except json.JSONDecodeError:
        print(f"Config file '{path}' is not valid JSON — using defaults")
        return DEFAULT_CONFIG

config = load_config('service_config.json')
print(config)

# Output (if service_config.json is missing):
# Config file 'service_config.json' not found — using defaults
# {'timeout': 30, 'retries': 3, 'log_level': 'INFO'}
```

**Why it matters:** Config files in production get deleted, truncated, or corrupted more often than anyone expects — catching these errors explicitly keeps a service booting with sane defaults instead of crash-looping.

### 5. Processing a Large File Efficiently

**Scenario:** A multi-gigabyte web server access log needs to be scanned for every `500` response code, but reading it all at once with `.read()` would blow up memory on the CI runner.

```python
def find_status_code(path, status_code):
    """Yields matching lines one at a time instead of loading the whole file."""
    with open(path, 'r') as f:
        for line in f:  # streaming, buffered iteration — memory-safe
            if f' {status_code} ' in line:
                yield line.strip()

count = 0
for match in find_status_code('access.log', '500'):
    count += 1

print(f"Found {count} requests with status 500")
# Output (example):
# Found 17 requests with status 500
```

**Why it matters:** Log and metrics files routinely outgrow available RAM — using a generator with buffered line iteration keeps processing fast and memory-flat regardless of file size.

## **2. Reading Files**

### **Methods**
1. **`read()`** - Entire content as string
   ```python
   with open('diary.txt', 'r') as f:
       diary_text = f.read()  # For small files
   ```

2. **`readline()`** - Single line at a time
   ```python
   with open('diary.txt', 'r') as f:
       while True:
           line = f.readline()
           if not line: break
           if 'grateful' in line:
               print(line)
   ```

3. **`readlines()`** - List of all lines
   ```python
   with open('friends.txt', 'r') as f:
       friends = f.readlines()  # ['Alice\n', 'Bob\n']
   ```

4. **Iteration (Memory Efficient)**
   ```python
   # Process a large diary archive
   with open('diary_archive.txt', 'r') as f:
       for line in f:  # Reads line-by-line
           if 'important' in line:
               highlight(line)
   ```

## **7. Best Practices**

1. **Always use `with` statements** - Ensures proper file closing
2. **Handle encodings explicitly** - Especially with cross-platform files
3. **Process large files line-by-line** - Avoid memory issues
4. **Validate file paths** - Check existence and permissions
5. **Use atomic writes** for important files:
   ```python
   import os
   temp_path = 'diary.tmp'
   final_path = 'diary.txt'
   
   with open(temp_path, 'w') as f:
       f.write(new_entry)
   os.replace(temp_path, final_path)  # Atomic operation
   ```
6. **Leverage `pathlib`** for modern path handling (Python 3.4+)
7. **Monitor file descriptors** in long-running processes
