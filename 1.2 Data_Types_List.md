## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Rolling update — process a deploy queue one instance at a time

**Scenario:** You're rolling out a new AMI across a fleet, one instance at a time, so you don't take everything down together.

```python
instances = ['i-101', 'i-102', 'i-103']

while instances:
    current = instances.pop(0)      # take the first instance off the queue
    print(f"Updating {current}...")
    # update_instance(current) would go here
    print(f"{current} done. {len(instances)} remaining.")
```
**Why it matters:** `pop(0)` + `while` is the standard pattern for draining a work queue safely, one item at a time.

### 2. Filter unhealthy pods from a status list

**Scenario:** You have pod statuses pulled from `kubectl` and want just the ones that need attention.

```python
pod_statuses = [
    {"name": "web-1", "status": "Running"},
    {"name": "web-2", "status": "CrashLoopBackOff"},
    {"name": "db-1", "status": "Running"},
    {"name": "cache-1", "status": "Pending"},
]

unhealthy = [p["name"] for p in pod_statuses if p["status"] != "Running"]
print(unhealthy)   # ['web-2', 'cache-1']
```
**Why it matters:** list comprehensions with a filter condition are how you'd write a one-line health-check alert generator.

### 3. Batch API calls to avoid rate limits

**Scenario:** Cloud APIs (AWS, GCP) often cap how many resource IDs you can pass per call. You need to chunk a big instance list into batches of 10.

```python
instance_ids = [f"i-{n:04d}" for n in range(1, 26)]   # 25 fake instance IDs

def batch(items, size):
    for i in range(0, len(items), size):
        yield items[i:i + size]

for chunk in batch(instance_ids, 10):
    print(f"Calling API with batch: {chunk}")
    # ec2.describe_instances(InstanceIds=chunk)
```
**Why it matters:** slicing (`items[i:i+size]`) is the core trick behind every "process in batches" script you'll write against a rate-limited API.

### 4. Detect config drift between desired and running instance types

**Scenario:** You want to compare the instance types Terraform expects against what's actually running, and flag anything unexpected.

```python
desired_types = ['t3.medium', 't3.medium', 'm5.large']
running_types = ['t3.medium', 'm5.large', 'm5.large']

# dedupe + sort both sides for a clean comparison
desired_unique = sorted(set(desired_types))
running_unique = sorted(set(running_types))

print(f"Desired: {desired_unique}")
print(f"Running: {running_unique}")

if desired_unique != running_unique:
    print("🔴 Drift detected between desired and running instance types")
else:
    print("✅ No drift")
```
**Why it matters:** `sorted(set(...))` is a quick way to normalize two lists before comparing them for infra drift.

### 5. Pair instances with their availability zones

**Scenario:** You have two parallel lists (instance IDs and AZs, e.g. from a CSV export) and need to combine them for a report.

```python
instance_ids = ['i-123', 'i-456', 'i-789']
azs = ['us-east-1a', 'us-east-1b', 'us-east-1c']

for instance, az in zip(instance_ids, azs):
    print(f"{instance} is in {az}")

# Build a report as a list of dicts
report = [{"instance": i, "az": a} for i, a in zip(instance_ids, azs)]
print(report)
```
**Why it matters:** `zip()` is the standard way to combine two related lists that come from separate sources (e.g. two CSV columns) without manual indexing.

## 📦 List Basics

- Written with `[ ]`, ordered, mutable, can mix data types
- Access elements by index (`0`-based), negative index counts from the end

```python
instance_ids = ['i-123456', 'i-789012', 'i-345678']
security_groups = ['web-sg', 'db-sg', 'admin-sg']

print(instance_ids[0])    # i-123456
print(instance_ids[-1])   # i-345678 (last element)
```

## 🏗 Creating Lists

```python
empty = []                                   # empty, for dynamic population
regions = ['us-east-1', 'us-west-2']          # pre-populated

from_tuple = list(('t2.micro', 't3.medium'))  # tuple -> list
from_string = list('abc')                      # 'abc' -> ['a', 'b', 'c']

# list comprehension — very common for building lists from a rule
ports = [p for p in range(1, 1024) if p % 2 == 0]     # even ports under 1024
```

## 🔍 Accessing & Slicing

```python
all_ports = [22, 80, 443, 3306, 5432, 8080]

print(all_ports[0])       # 22        — first element
print(all_ports[-1])      # 8080      — last element
print(all_ports[1:3])     # [80, 443] — slice from index 1 up to (not including) 3
print(all_ports[-3:])     # [3306, 5432, 8080] — last three
```

## ✏️ Modifying Lists

```python
security_groups = ['web-sg', 'db-sg', 'admin-sg']

security_groups.append('bastion-sg')             # add one item at the end
security_groups.extend(['monitoring-sg', 'logging-sg'])   # add multiple items
security_groups.insert(1, 'loadbalancer-sg')     # insert at a specific position
security_groups[0] = 'web-frontend-sg'           # modify by index
security_groups.remove('db-sg')                   # remove by value (first match)
del security_groups[2]                             # remove by index
security_groups.clear()                             # empty the list

print(security_groups)   # []
```

## 🧰 List Methods Reference

| Method       | What it does                    | Example                                  |
| ------------- | ---------------------------------- | -------------------------------------------- |
| `.append(x)`  | add one item at the end            | `logs.append(entry)`                         |
| `.extend(it)` | add all items from another list    | `all_sgs.extend(new_sgs)`                    |
| `.insert(i,x)`| insert item at index `i`           | `tasks.insert(0, 'urgent-fix')`              |
| `.remove(x)`  | remove first item equal to `x`     | `instances.remove('i-failed')`               |
| `.pop([i])`   | remove & return item (default last)| `queue.pop(0)`                                |
| `.index(x)`   | position of first match            | `regions.index('eu-west-1')`                 |
| `.count(x)`   | how many times `x` appears         | `statuses.count('failed')`                   |
| `.sort()`     | sort in place                      | `sizes.sort()`                                |
| `.reverse()`  | reverse order in place             | `steps.reverse()`                             |
| `.copy()`     | shallow copy                       | `backup = config.copy()`                      |
| `sorted(list)`| return a **new** sorted list       | `sorted(usage, reverse=True)`                 |
| `len(list)`   | number of items                    | `len(instances)`                              |

⚠️ `.sort()`/`.reverse()` change the list in place and return `None`. `sorted()`/`reversed()` return a new list/iterator and leave the original untouched — use whichever fits (don't `print(mylist.sort())`, it prints `None`).

```python
# rolling replacement of instances
instances = ['i-1', 'i-2', 'i-3']
while instances:
    current = instances.pop(0)
    print(f"Replacing {current}")
```

## 🔁 Iteration Patterns

```python
instance_ids = ['i-1', 'i-2', 'i-3']

# basic loop
for instance_id in instance_ids:
    print(instance_id)

# with a step counter (enumerate)
for step_num, step in enumerate(['build', 'test', 'deploy'], 1):
    print(f"Step {step_num}: {step}")

# transform with a comprehension
arns = [f"arn:aws:ec2:us-east-1:123:instance/{i}" for i in instance_ids]
```

## 🪆 Nested Lists

Used to represent grouped infrastructure, e.g. resources per availability zone.

```python
az_resources = [
    ['web-1a', 'db-1a', 'cache-1a'],
    ['web-1b', 'db-1b', 'cache-1b'],
]

print(az_resources[0][1])   # 'db-1a' — second item of the first AZ's list
```

## ⚖️ Lists vs Other Types

| Use a `list` when...            | Use something else when...                  |
| ---------------------------------- | ------------------------------------------------ |
| order matters (deploy steps)        | you don't care about order → `set`               |
| you need to modify the collection   | data shouldn't change → `tuple`                   |
| items are accessed by position      | items are looked up by name/key → `dict`         |
| you check membership rarely         | you check membership a lot → `set` (`in` is O(1)) |

---

## ⚙️ Performance Notes

| Operation      | Complexity | Practical impact                       |
| --------------- | ------------ | ------------------------------------------ |
| index access `[i]` | O(1)     | fast — safe to use freely                  |
| `.append()`     | O(1)         | efficient for growing a log/collection      |
| `.insert(0, x)` | O(n)         | slow for large lists — everything shifts    |
| `x in list`     | O(n)         | slow for big lists — use a `set` instead    |

```python
# faster membership testing for large collections
allowed_ports = {22, 80, 443, 3306}    # set, not list
if port in allowed_ports:               # O(1) instead of O(n)
    allow_traffic(port)
```
