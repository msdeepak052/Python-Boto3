## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Retry Loop with a Max-Attempts Break

**Scenario:** A deployment script needs to poll a Kubernetes pod until it reaches the `Running` state, but should give up cleanly instead of retrying forever if the pod never comes up.

```python
import time

def get_pod_status(pod_name, attempt):
    """Simulates a flaky Kubernetes API call that succeeds on the 3rd attempt."""
    return "Running" if attempt >= 3 else "Pending"

pod_name = "web-app-7d9f8c-x2k9p"
max_attempts = 5
attempt = 1

while attempt <= max_attempts:
    status = get_pod_status(pod_name, attempt)
    if status == "Running":
        print(f"Pod '{pod_name}' is Running after {attempt} attempt(s).")
        break  # stop retrying — we got what we wanted
    print(f"Attempt {attempt}: pod status is '{status}', retrying...")
    attempt += 1
    time.sleep(1)  # brief backoff between retries
else:
    # Only runs if the while condition became False without hitting 'break'
    print(f"Gave up after {max_attempts} attempts — pod never became Running.")

# Output:
# Attempt 1: pod status is 'Pending', retrying...
# Attempt 2: pod status is 'Pending', retrying...
# Pod 'web-app-7d9f8c-x2k9p' is Running after 3 attempt(s).
```

**Why it matters:** Almost every deployment or infrastructure script waits on something eventually consistent (pods, DNS, load balancer health checks). A bounded retry loop with `break` prevents your automation from either giving up too early or hanging forever.

**Scenario:** A platform team needs to apply a resource quota to every namespace in a cluster and wants clear numbered progress output for the CI job logs.

```python
namespaces = ["billing", "auth", "frontend", "analytics", "notifications"]

for index, namespace in enumerate(namespaces, start=1):
    print(f"[{index}/{len(namespaces)}] Applying resource quota to namespace: {namespace}")
    # In a real script this would call the Kubernetes API client, e.g.:
    # apply_resource_quota(namespace)

# Output:
# [1/5] Applying resource quota to namespace: billing
# [2/5] Applying resource quota to namespace: auth
# [3/5] Applying resource quota to namespace: frontend
# [4/5] Applying resource quota to namespace: analytics
# [5/5] Applying resource quota to namespace: notifications
```

**Why it matters:** `enumerate()` gives you a clean progress counter without manually maintaining an index variable — invaluable when batch-processing pods, namespaces, or cloud resources and you want log output that's easy to scan during a rollout.

### 3. Polling for a Status Change (While Loop)

**Scenario:** A CI/CD script triggers a pipeline run and must wait until it finishes before continuing to the next stage of the workflow.

```python
import time

# Simulates a sequence of responses from a CI/CD status API
status_sequence = iter(["in_progress", "in_progress", "in_progress", "succeeded"])

def poll_pipeline_status():
    return next(status_sequence)

run_id = "run-48213"
status = poll_pipeline_status()

while status == "in_progress":
    print(f"Pipeline {run_id} is still running... checking again in 5s")
    time.sleep(5)
    status = poll_pipeline_status()

print(f"Pipeline {run_id} finished with status: {status}")

# Output:
# Pipeline run-48213 is still running... checking again in 5s
# Pipeline run-48213 is still running... checking again in 5s
# Pipeline run-48213 is still running... checking again in 5s
# Pipeline run-48213 finished with status: succeeded
```

**Why it matters:** Polling is the backbone of CI/CD orchestration — waiting on a Terraform apply, a pipeline run, or an image build. A `while` loop keyed on the current status is the simplest reliable way to express "wait until this changes."

### 4. Building a Report from a List of Records (For Loop)

**Scenario:** After a multi-service release, a script needs to turn a list of per-service deployment records into a readable summary report for the team channel.

```python
deployments = [
    {"service": "auth-api", "version": "2.3.1", "status": "success"},
    {"service": "billing-api", "version": "1.9.0", "status": "failed"},
    {"service": "frontend", "version": "4.0.2", "status": "success"},
]

report_lines = ["Deployment Report", "=================="]
success_count = 0

for record in deployments:
    line = f"{record['service']} v{record['version']} -> {record['status'].upper()}"
    report_lines.append(line)
    if record["status"] == "success":
        success_count += 1

report_lines.append(f"\n{success_count}/{len(deployments)} deployments succeeded.")
report = "\n".join(report_lines)
print(report)

# Output:
# Deployment Report
# ==================
# auth-api v2.3.1 -> SUCCESS
# billing-api v1.9.0 -> FAILED
# frontend v4.0.2 -> SUCCESS
#
# 2/3 deployments succeeded.
```

**Why it matters:** Turning raw API/record data into a human-readable summary is one of the most common things automation scripts do — release notes, health-check summaries, cost reports. A simple `for` loop with an accumulator is usually all you need.

### 5. Nested Loops for a Grid of Nodes

**Scenario:** A data center health-check script needs to scan every node in every rack — a two-dimensional grid — and report which ones are unhealthy.

```python
# Simulate a data center layout: 3 racks, each with 4 node slots
racks = ["rack-1", "rack-2", "rack-3"]
slots_per_rack = 4
known_unhealthy = {("rack-2", 3)}  # simulate one bad node for this demo

def check_node_health(rack, slot):
    return "unhealthy" if (rack, slot) in known_unhealthy else "healthy"

unhealthy_nodes = []

for rack in racks:
    print(f"Scanning {rack}:")
    for slot in range(1, slots_per_rack + 1):
        node_id = f"{rack}-node-{slot}"
        health = check_node_health(rack, slot)
        print(f"  {node_id}: {health}")
        if health == "unhealthy":
            unhealthy_nodes.append(node_id)

print(f"\n{len(unhealthy_nodes)} unhealthy node(s) found: {unhealthy_nodes}")

# Output:
# Scanning rack-1:
#   rack-1-node-1: healthy
#   rack-1-node-2: healthy
#   rack-1-node-3: healthy
#   rack-1-node-4: healthy
# Scanning rack-2:
#   rack-2-node-1: healthy
#   rack-2-node-2: healthy
#   rack-2-node-3: unhealthy
#   rack-2-node-4: healthy
# Scanning rack-3:
#   rack-3-node-1: healthy
#   rack-3-node-2: healthy
#   rack-3-node-3: healthy
#   rack-3-node-4: healthy
#
# 1 unhealthy node(s) found: ['rack-2-node-3']
```

**Why it matters:** Infrastructure is frequently laid out as a grid — racks and slots, regions and zones, clusters and nodes. Nested `for` loops are the natural way to walk that grid, and keeping the inner loop's body small (one health check per node) keeps the scan easy to reason about and extend.

For loops are fundamental to everyday programming, enabling iteration over lists of items, recipe steps, and everyday records. This guide covers all aspects of `for` loops with practical, easy-to-follow examples using a home kitchen and grocery shopping theme.

## **1. Basic `for` Loop Syntax**

### **Structure**
```python
for item in iterable:
    # Code to execute
else:
    # Optional: Runs after loop completes (unless 'break' is called)
```

### **Simple Example**
```python
# Iterate over grocery list items
grocery_items = ['apples', 'bread', 'milk']
for item in grocery_items:
    print(f"Checking off {item}")
    mark_item_purchased(item)
```

## **2. Iterating Different Data Types**

### **Lists (Most Common Type)**
```python
# Process recipe steps
recipe_steps = ["chop vegetables", "boil water", "cook pasta"]
for step in recipe_steps:
    do_step(step)
```

### **Dictionaries (Item Labels)**
```python
pantry_labels = {"Category": "grains", "Shelf": "top", "Item": "rice"}

# Iterate keys
for label_key in pantry_labels:
    print(f"Label key: {label_key}")

# Iterate key-value pairs
for key, value in pantry_labels.items():
    print(f"{key}: {value}")

# Use Case: Convert labels to a shopping-list format
shopping_labels = [{"Label": k, "Value": v} for k, v in pantry_labels.items()]
```

### **Sets (Unique Values)**
```python
# Check allowed oven temperatures
allowed_temps = {350, 375, 400}
for temp in allowed_temps:
    validate_temp(temp)
```

### **Strings (Text Files)**
```python
# Process each line in a recipe card file
def update_cook_time():
    updated_line = "cook_time = 20 minutes\n"  # The new line to replace with

    # Read all lines from the file
    with open('recipe.txt', 'r') as file:
        lines = file.readlines()

    # Write back lines, replacing the matching cook_time line
    with open('recipe.txt', 'w') as file:
        for line in lines:
            if line.strip().startswith("cook_time"):
                file.write(updated_line)
            else:
                file.write(line)
update_cook_time()

```

## **3. Advanced Loop Control**

### **`break` (Early Termination)**
```python
# Stop at first spoiled grocery item
for item in groceries:
    if not check_freshness(item):
        alert(f"Item {item} is spoiled")
        break
```

### **`continue` (Skip Iteration)**
```python
# Skip sample-size items
for item in groceries:
    if item.startswith('sample-'):
        continue
    process_item(item)
```

### **`else` Clause (Completion Handler)**
```python
# Verify all groceries are checked off
for item in groceries:
    if item['Status'] != 'checked':
        break
else:
    print("All groceries are checked off the list")
```

## **4. Built-in Functions for Loops**

### **`range()` (Numerical Iteration)**
```python
# Retry a slow self-checkout scan

    try:
        response = scan_item()
        break
    except ScannerError:
        if attempt == 2:
            raise
        time.sleep(1)
```

### **`enumerate()` (Index + Value)**
```python
# Track recipe step numbers
for step_num, step in enumerate(recipe_steps, start=1):
    print(f"Step {step_num}: {step}")
    do_step(step)
```

### **`zip()` (Parallel Iteration)**
```python
# Pair grocery items with their aisles
items = ['bread', 'milk']
aisles = ['Aisle 3', 'Aisle 7']
for item, aisle in zip(items, aisles):
    print(f"{item} is in {aisle}")
```

## **8. Best Practices**

1. **Use `try-except` in loops** to handle scanner/printer failures gracefully
2. **Limit store trips** with batch shopping (avoid overloading the cart)
3. **Prefer generators** (`yield`) for large datasets
4. **Add progress indicators** in long-running loops
5. **Use `tqdm`** for progress bars:
   ```python
   from tqdm import tqdm
   for item in tqdm(groceries, desc="Checking off items"):
       update_item(item)
   ```
6. **Avoid nested loops** when possible (consider `itertools.product`)
7. **Document loop purposes** for complex iterations

# **Python `while` Loops: A Comprehensive Guide**

While loops are essential for tasks requiring continuous monitoring, retry logic, and conditional iteration in everyday life. This guide covers all aspects of `while` loops with practical, easy-to-follow examples using a home kitchen and grocery shopping theme.

## **1. Basic `while` Loop Syntax**

### **Structure**
```python
while condition:
    # Code to execute
else:
    # Optional: Runs when loop completes (unless 'break' is called)
```

### **Simple Example**
```python
# Wait for the oven to reach the target temperature
max_attempts = 12
while get_oven_temp() != target_temp and max_attempts > 0:
    print(f"Current temp: {get_oven_temp()}")
    time.sleep(5)
    max_attempts -= 1
else:
    if max_attempts == 0:
        raise TimeoutError("Oven failed to preheat")
```

## **2. Key While Loop Patterns**

### **1. Continuous Monitoring**
```python
# Monitor fridge temperature indefinitely
while True:
    status = check_fridge_temp('kitchen-fridge')
    if status != 'normal':
        adjust_thermostat('kitchen-fridge')
    time.sleep(60)  # Check every minute
```

### **2. Retry Logic for Phone Orders**
```python
# Retry a failed call to the pizza delivery hotline with exponential backoff
attempt = 1
max_retries = 5
base_delay = 1  # second

while attempt <= max_retries:
    try:
        response = call_delivery_hotline(order_id)
        break
    except LineBusyError as e:
        if attempt == max_retries:
            raise
        delay = base_delay * (2 ** (attempt - 1))
        time.sleep(delay)
        attempt += 1
```

### **3. Waiting for Dough to Rise**
```python
# Wait for bread dough to finish rising
dough_status = ''
while dough_status not in ['RISEN', 'DOUBLE_SIZE']:
    response = check_dough(batch_name='sourdough-batch-1')
    dough_status = response['Batches'][0]['Status']
    if dough_status.endswith('FAILED'):
        raise Exception("Dough failed to rise")
    time.sleep(10)
```

## **3. Advanced Control Flow**

### **`break` (Immediate Exit)**
```python
# Process the shopping list until an out-of-stock item is found
while True:
    list_entry = get_next_list_item()
    if 'OUT_OF_STOCK' in list_entry:
        alert_team(list_entry)
        break
    process_list_item(list_entry)
```

### **`continue` (Skip Current Iteration)**
```python
# Skip processing of sample-size items
items = get_all_items()
index = 0
while index < len(items):
    if items[index].startswith('sample-'):
        index += 1
        continue
    process_item(items[index])
    index += 1
```

### **`else` Clause (Completion Handler)**
```python
# Verify all ingredients are fresh
unhealthy_count = 3  # Allowed threshold
while unhealthy_count > 0:
    if not check_ingredient_freshness():
        unhealthy_count -= 1
    time.sleep(5)
else:
    print("All ingredients checked and fresh")
```

## **4. Real-World Examples**

### **1. Cooking Multiple Dishes in Sequence**

```python
    else:
        current += 1  # Only advance if successful
```

## **5. Performance and Safety Considerations**

### **1. Avoiding Infinite Loops**
```python
# Always include a termination condition
timeout = time.time() + 300  # 5 minutes from now
while laundry_not_ready():
    if time.time() > timeout:
        raise TimeoutError("Laundry cycle timed out")
    time.sleep(5)
```

### **2. Avoiding Constant Checking**
```python
# Use sleep() for polling scenarios
while True:
    mail_available = check_mailbox()
    if not mail_available:
        time.sleep(0.1)  # Avoids constantly checking the mailbox
        continue
    process_next_mail()
```

### **3. Memory Management**
```python
# Process large files line by line
with open('large_recipe_book.txt') as f:
    while True:
        line = f.readline()
        if not line:
            break
        process_recipe_line(line)
```

## **6. Comparison with `for` Loops**

| **Scenario**              | **`while` Loop**                          | **`for` Loop**                     |
|---------------------------|------------------------------------------|------------------------------------|
| Unknown iteration count   | ✅ Best (e.g., waiting for water to boil) | ❌ Not suitable                    |
| Fixed sequence processing | ❌ Verbose                               | ✅ Best (e.g., list of grocery items) |
| Continuous monitoring     | ✅ Ideal                                 | ❌ Not designed for this           |
| Error recovery           | ✅ Built-in retry logic                  | ❌ Requires external counter       |

## **7. Best Practices**

1. **Always include a timeout** - Prevent infinite loops in real programs
2. **Use exponential backoff** - For retrying phone or network calls
3. **Add sleep intervals** - Reduce unnecessary repeated checks in polling scenarios

# Loop Control Statements (break and continue)

## Introduction

Loop control statements are used to modify the behavior of loops, providing greater control and flexibility during iteration. In Python, two primary loop control statements are "break" and "continue."

## `break` Statement

The "break" statement is used to exit the loop prematurely. It can be applied to both "for" and "while" loops, allowing you to terminate the loop when a particular condition is met.

**Example:**

```python
numbers = [1, 2, 3, 4, 5]
for number in numbers:
    if number == 3:
        break
    print(number)
```

**Output:**

```
1
2
```

In this example, the loop stops when it encounters the number 3.

## `continue` Statement

The "continue" statement is used to skip the current iteration of the loop and proceed to the next one. It can be used in both "for" and "while" loops, enabling you to bypass certain iterations based on a condition.

**Example:**

```python
numbers = [1, 2, 3, 4, 5]
for number in numbers:
    if number == 3:
        continue
    print(number)
```

**Output:**

```
1
2
4
5
```

In this example, the loop skips the iteration where the number is 3 and continues with the next iteration.
