## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

Real scenarios solved end-to-end so you can see tuples used the way you'd actually use them on the job.

### 1. Lock down allowed deployment regions

**Scenario:** Your deploy script should only ever target a fixed set of regions — this list must never be accidentally modified at runtime.

```python
ALLOWED_REGIONS = ('us-east-1', 'us-west-2', 'eu-west-1')   # tuple = can't be changed

def deploy(region):
    if region not in ALLOWED_REGIONS:
        raise ValueError(f"Region {region} not allowed. Choose from {ALLOWED_REGIONS}")
    print(f"Deploying to {region}")

deploy('us-west-2')     # ✅ works
# deploy('ap-south-1')  # ❌ raises ValueError
```
**Why it matters:** using a tuple (not a list) for constants is a signal — and a guarantee — that this data is fixed configuration, not something a later bug could mutate.

---

### 2. Return multiple health-check values from a function

**Scenario:** A monitoring function checks an instance and needs to return three related values at once.

```python
def check_instance_health(instance_id):
    status = "running"       # normally from a real API call
    cpu_util = 42.5
    mem_util = 61.2
    return status, cpu_util, mem_util   # packed into a tuple automatically

status, cpu, mem = check_instance_health('i-123456')   # unpacked on return
print(f"{status=} {cpu=} {mem=}")

if cpu > 90:
    print("🔺 Scale out needed")
```
**Why it matters:** returning a tuple (`a, b, c`) is the standard Python way to return multiple values — no need for a class or dict for something this simple.

---

### 3. Model a server record with a named tuple

**Scenario:** You want a lightweight, readable structure for a server (not a full class) that's still immutable.

```python
from collections import namedtuple

Server = namedtuple('Server', ['id', 'type', 'zone', 'status'])

web = Server(id='i-123456', type='t2.large', zone='us-east-1a', status='running')

print(f"Instance {web.id} is {web.status} in {web.zone}")   # access by name
print(web[0])    # 'i-123456' — also accessible by index

# web.status = 'stopped'   # ❌ TypeError — named tuples are still immutable
```
**Why it matters:** `namedtuple` gives you `dict`-like readability (`web.status` instead of `web[3]`) while staying memory-efficient and immutable — great for read-only records like CMDB entries.

### 4. Compare software/API versions

**Scenario:** You need to check if a deployed service's version meets a minimum requirement before allowing an upgrade to proceed.

```python
MIN_VERSION = (2, 3, 1)
current_version = (2, 4, 0)

if current_version < MIN_VERSION:
    print("🔴 Must upgrade before proceeding")
else:
    print("✅ Version requirement met")

# Python compares tuples element by element, left to right — exactly like semver
print((1, 5, 3) < (1, 6, 0))   # True, because 5 < 6
print((1, 4) < (1, 4, 1))       # True, shorter tuple is "smaller"
```
**Why it matters:** tuple comparison gives you correct semantic-version comparisons for free — no string parsing needed.

### 5. Use a composite key to map region+zone to a subnet

**Scenario:** Your Terraform-generated subnet map needs a compound lookup key: (region, availability zone) → subnet ID.

```python
subnet_map = {
    ('us-east-1', 'a'): 'subnet-0a1b2c',
    ('us-east-1', 'b'): 'subnet-0d3e4f',
    ('us-west-2', 'a'): 'subnet-0g5h6i',
}

lookup = ('us-east-1', 'b')
print(subnet_map[lookup])   # subnet-0d3e4f
```
**Why it matters:** only immutable types can be dict keys — tuples are the natural choice for composite/compound keys like `(region, az)`.

## **1. Tuple Fundamentals**

### **What is a Tuple?**
An ordered, immutable collection of elements that can contain mixed data types.

```python
# examples:
STORE_BRANCHES = ('Downtown', 'Uptown', 'Midtown')  # Immutable branch list
PRODUCT = ('apple', 1, 0.99)  # Name, quantity, price
```

### **Key Characteristics**
- **Immutable**: Cannot be modified after creation
- **Ordered**: Maintains element position
- **Heterogeneous**: Can store different data types
- **Hashable**: Can be used as dictionary keys (if all elements are hashable)
- **Memory Efficient**: More lightweight than lists

> “If tuples are immutable, why doesn’t this code throw an error when I reassign or add them?”

---

### 🔍 The Key Concept: **Immutability ≠ Unchangeable Variable**

In Python, **tuples are immutable**, which means:

* Once a tuple is **created**, its **contents cannot be changed in-place** (no item assignment, deletion, etc.).
* But you can **reassign the variable** that refers to the tuple — this is **not changing the tuple**, it’s just pointing the variable to a **new tuple object**.

---

### ✅ Let’s break your code:

```python
regular_prices = (1.99, 3.49, 4.99)
sale_prices = (0.99, 2.49)

# This creates a new tuple by combining two tuples
regular_prices = regular_prices + sale_prices  
# Now regular_prices = (1.99, 3.49, 4.99, 0.99, 2.49)

print(regular_prices)

# Here you're assigning a completely new tuple to the same variable
regular_prices = (1.99, 3.49, 5.99)
print(regular_prices)
```

At no point are you modifying the **original tuple object** — you're just **reassigning the variable** `regular_prices` to new tuple values.

---

### ❌ What *would* cause an error with a tuple?

Trying to change its **contents in-place**:

```python
t = (1, 2, 3)
t[0] = 99      # ❌ This will raise TypeError
```

**Output:**

```python
TypeError: 'tuple' object does not support item assignment
```

---

### 📌 Summary

| Action                  | Allowed? | Why?                                          |
| ----------------------- | -------- | ---------------------------------------------- |
| `tuple_var = (1, 2, 3)` | ✅ Yes    | Creating a tuple                              |
| `tuple_var[0] = 99`     | ❌ No     | Tuples are immutable                          |
| `tuple_var = (4, 5, 6)` | ✅ Yes    | Reassigning the variable, not modifying tuple |
| `tuple_var += (7,)`     | ✅ Yes    | Creates a new tuple and rebinds the variable  |

## **6. Advanced Tuple Techniques**

### **Named Tuples (Readable Structures)**
```python
from collections import namedtuple

# Define a product structure
Product = namedtuple('Product', ['id', 'name', 'price', 'category'])

# Create instance
apple = Product(
    id='P-1001',
    name='Apple',
    price=0.99,
    category='produce'
)

# Access fields
print(f"Product {apple.id} costs ${apple.price}")
```

We're using `namedtuple` from Python's `collections` module — this is a **powerful and elegant** way to create **lightweight, immutable data structures** that behave like classes but are more memory-efficient and readable.

---

### 🔍 What is `namedtuple`?

`namedtuple()` lets you create tuple-like objects with **named fields** instead of using index-based access.

* ✅ More readable than plain tuples
* ✅ Immutable (just like regular tuples)
* ✅ Access fields by name **and** by index
* ✅ Lightweight alternative to defining a full class

---

### ✅ Your Code Explained

```python
from collections import namedtuple

# Define a Product namedtuple with 4 fields
Product = namedtuple('Product', ['id', 'name', 'price', 'category'])
```

* This creates a new type called `Product` with the fields:

  * `id`, `name`, `price`, `category`

---

```python
# Create an instance of Product
apple = Product(
    id='P-1001',
    name='Apple',
    price=0.99,
    category='produce'
)
```

* `apple` is now an object of type `Product`.
* Fields can be accessed like attributes: `apple.id`, `apple.price`, etc.

---

```python
# Print a formatted message using field values
print(f"Product {apple.id} costs ${apple.price}")
```

### 🖨️ Output:

```
Product P-1001 costs $0.99
```

---

### 🔁 Access by Index (Like Regular Tuples)

```python
print(apple[1])  # Output: Apple
```

---

### ❌ Immutable — You can't modify fields

```python
apple.price = 1.29  # ❌ TypeError
```

---

### ✅ Summary

| Feature                    | Explanation                                    |
| --------------------------- | ------------------------------------------------ |
| `namedtuple`               | Factory function to create tuple-like classes  |
| Field access               | By name (`apple.price`) or index `[2]`         |
| Memory efficient           | Smaller than full classes                      |
| Immutable                  | Fields can't be changed after creation         |
| Cleaner than dict or tuple | Self-documenting code, no guessing by position |

## **9. Best Practices**

1. **Use tuples for constants**: `ESSENTIAL_ITEMS = ('bread', 'milk', 'eggs')`
2. **Return multiple values**: Functions should return tuples for multiple values
3. **Prefer tuples for dict keys**: 
   ```python
   product_locations = {('Downtown', 'A'): 'P-100', ('Uptown', 'B'): 'P-200'}
   ```
4. **Use named tuples**: When you need field names
5. **Immutable configurations**: For settings that shouldn't change at runtime
6. **Type hints**: 
   ```python
   def get_product() -> tuple[str, str, float]:  # name, category, price
   ```

## **10. When Not to Use Tuples**

1. **Need to modify collections**: Use lists instead
2. **Frequent appending/removing**: Lists or deque are better
3. **Single-element collections**: Remember the trailing comma
4. **Complex nested structures**: Consider dictionaries or dataclasses

- **Safe data passing between components**

Their immutability provides safety in everyday programs, while their lightweight nature makes them ideal for performance-critical operations. Mastering tuples leads to more robust, maintainable, and efficient Python code.

# **Tuple Built-in Functions in Python: Comprehensive Guide**

Tuples are immutable sequences that play a vital role in Python for grouping related values, keeping data safe from accidental changes, and returning multiple values from functions. This guide covers all tuple-related built-in functions with practical, everyday examples.

## **1. Core Tuple Functions**

### **`len()` - Get Tuple Length**
Returns the number of items in a tuple.

```python
cart_items = ('apple', 'bread', 'milk', 'eggs')
print(len(cart_items))  # Output: 4

# Use Case: Validate minimum requirements
ESSENTIAL_ITEMS = ('bread', 'milk', 'eggs')
if len(cart_items) < len(ESSENTIAL_ITEMS):
    raise ValueError("Missing essential items")
```

### **`tuple()` - Tuple Constructor**
Creates a tuple from an iterable.

```python
# Convert list to tuple (making it immutable)
product_ids = tuple(['P-100', 'P-200'])

# Convert daily sales data points
sales = tuple(get_daily_sales())

# Convert dictionary items
labels = tuple({'Organic': 'Yes', 'Local': 'Yes'}.items())
# (('Organic', 'Yes'), ('Local', 'Yes'))
```

## **2. Tuple Access Functions**

### **`index()` - Find Element Position**
Returns the first index where value is found.

```python
payment_methods = ('cash', 'card', 'gift_card', 'check')
card_pos = payment_methods.index('card')  # 1

# Example: Validate allowed payment methods
try:
    crypto_pos = payment_methods.index('crypto')
except ValueError:
    print("Crypto payment not accepted - not a supported method")
```

**Parameters:**
- `value`: Element to search for
- `start` (optional): Index to start search
- `end` (optional): Index to end search

```python
statuses = ('pending', 'shipped', 'delivered', 'shipped')
first_shipped = statuses.index('shipped')  # 1
second_shipped = statuses.index('shipped', 2)  # 3
```

### **`count()` - Count Element Occurrences**
Returns number of occurrences of a value.

```python
deliveries = ('on_time', 'late', 'on_time', 'on_time')
on_time_count = deliveries.count('on_time')  # 3

# Use Case: Delivery performance check
if deliveries.count('late') > 0:
    flag_for_review()
```

## **6. Tuple Comparison**

### **Element-wise Comparison**
```python
best_before1 = (2026, 3, 15)
best_before2 = (2026, 6, 1)
print(best_before1 < best_before2)  # True (March 15 is before June 1)

# Example: Best-before date validation
EXPIRY_CUTOFF = (2026, 3, 1)
item_best_before = get_best_before_date()
if item_best_before < EXPIRY_CUTOFF:
    remove_from_shelf()
```

You're comparing two **tuples** representing dates:

```python
best_before1 = (2026, 3, 15)
best_before2 = (2026, 6, 1)
print(best_before1 < best_before2)  # True
```

---

### ✅ How It Works: Tuple Comparison in Python

Python compares tuples **element by element**, **left to right**, just like how calendar dates are typically compared.

So this line:

```python
best_before1 < best_before2
```

is equivalent to:

```python
(2026, 3, 15) < (2026, 6, 1)
```

---

### 🧠 Step-by-Step Comparison:

1. Compare first element: `2026 < 2026` → ❌ No (Equal) → Go to next
2. Compare second element: `3 < 6` → ✅ Yes → So entire comparison is **True**
3. (Python stops here — no need to check the 3rd value)

---

### 🧪 More Examples

```python
print((2026, 1, 20) < (2026, 1, 21))   # True → because 20 < 21
print((2026, 12, 1) > (2025, 12, 31))  # True → because 2026 > 2025
print((2026, 3) < (2026, 3, 1))        # True → shorter tuple is considered smaller
print((2026, 3, 15) == (2026, 3, 15))  # True → all elements match
```

---

### 📌 Summary

| Tuple1        | Tuple2       | Result  | Reason                 |
| ------------- | ------------ | ------- | ----------------------- |
| (2026, 3, 15) | (2026, 6, 1) | ✅ True  | 3 < 6                  |
| (2026, 3, 15) | (2026, 2, 9) | ❌ False | 3 > 2                  |
| (2026, 3)     | (2026, 3, 1) | ✅ True  | shorter tuple < longer |

---

This is **exactly why Python tuples are great** for comparing dates — no extra logic needed!

import sys

from timeit import timeit

## **10. Best Practices**

1. **Use tuples for constants**: `ESSENTIAL_ITEMS = ('bread', 'milk', 'eggs')`
2. **Return multiple values**: Functions should return tuples
3. **Prefer tuples for dict keys**: 
   ```python
   store_map = {('Downtown', 'A'): 'P-100'}
   ```
4. **Use named tuples**: When field names improve readability
5. **Immutable configs**: For settings that shouldn't change at runtime
6. **Type hints**: 
   ```python
   def get_order() -> tuple[str, str, int]:  # (id, item, quantity)
   ```

Tuple built-in functions enable Python programmers to:

- **Implement memory-efficient data structures**
