# Python Tuples

A `tuple` is an ordered, **immutable** collection — used whenever data shouldn't change after it's created (config constants, fixed records, function returns).

## 🖐 5 Hands-On Exercises — Platform Engineering Use Cases

### 1. Lock down allowed deployment regions

**Scenario:** Your deploy script should only ever target a fixed set of regions — this list must never be accidentally modified at runtime.

```python
ALLOWED_REGIONS = ('us-east-1', 'us-west-2', 'eu-west-1')   # tuple = can't be changed

def deploy(region):
    if region not in ALLOWED_REGIONS:
        raise ValueError(f"Region {region} not allowed. Choose from {ALLOWED_REGIONS}")
    print(f"Deploying to {region}")

deploy('us-west-2')     # ✅ works
# deploy('ap-south-1')  # ❌ raises ValueError
```
**Why it matters:** using a tuple (not a list) for constants is a signal — and a guarantee — that this data is fixed configuration, not something a later bug could mutate.

### 2. Return multiple health-check values from a function

**Scenario:** A monitoring function checks an instance and needs to return three related values at once.

```python
def check_instance_health(instance_id):
    status = "running"       # normally from a real API call
    cpu_util = 42.5
    mem_util = 61.2
    return status, cpu_util, mem_util   # packed into a tuple automatically

status, cpu, mem = check_instance_health('i-123456')   # unpacked on return
print(f"{status=} {cpu=} {mem=}")

if cpu > 90:
    print("🔺 Scale out needed")
```
**Why it matters:** returning a tuple (`a, b, c`) is the standard Python way to return multiple values — no need for a class or dict for something this simple.

### 3. Model a server record with a named tuple

**Scenario:** You want a lightweight, readable structure for a server (not a full class) that's still immutable.

```python
from collections import namedtuple

Server = namedtuple('Server', ['id', 'type', 'zone', 'status'])

web = Server(id='i-123456', type='t2.large', zone='us-east-1a', status='running')

print(f"Instance {web.id} is {web.status} in {web.zone}")   # access by name
print(web[0])    # 'i-123456' — also accessible by index

# web.status = 'stopped'   # ❌ TypeError — named tuples are still immutable
```
**Why it matters:** `namedtuple` gives you `dict`-like readability (`web.status` instead of `web[3]`) while staying memory-efficient and immutable — great for read-only records like CMDB entries.

---

### 4. Compare software/API versions

**Scenario:** You need to check if a deployed service's version meets a minimum requirement before allowing an upgrade to proceed.

```python
MIN_VERSION = (2, 3, 1)
current_version = (2, 4, 0)

if current_version < MIN_VERSION:
    print("🔴 Must upgrade before proceeding")
else:
    print("✅ Version requirement met")

# Python compares tuples element by element, left to right — exactly like semver
print((1, 5, 3) < (1, 6, 0))   # True, because 5 < 6
print((1, 4) < (1, 4, 1))       # True, shorter tuple is "smaller"
```
**Why it matters:** tuple comparison gives you correct semantic-version comparisons for free — no string parsing needed.

---

### 5. Use a composite key to map region+zone to a subnet

**Scenario:** Your Terraform-generated subnet map needs a compound lookup key: (region, availability zone) → subnet ID.

```python
subnet_map = {
    ('us-east-1', 'a'): 'subnet-0a1b2c',
    ('us-east-1', 'b'): 'subnet-0d3e4f',
    ('us-west-2', 'a'): 'subnet-0g5h6i',
}

lookup = ('us-east-1', 'b')
print(subnet_map[lookup])   # subnet-0d3e4f
```
**Why it matters:** only immutable types can be dict keys — tuples are the natural choice for composite/compound keys like `(region, az)`.

## 📚 Tuple Basics

- Written with `( )`, ordered, **immutable** (cannot change after creation)
- Can hold mixed data types, just like a list
- More memory-efficient and slightly faster to create than a list

```python
AWS_REGIONS = ('us-east-1', 'us-west-2', 'eu-west-1')
INSTANCE_SPEC = ('t2.micro', 1, 1.0)     # type, vCPUs, GiB memory

print(AWS_REGIONS[0])   # us-east-1
```

## 🏗 Creating Tuples

```python
empty = ()
single = ('prod',)          # ⚠️ trailing comma required, or it's just a string in parens
ports = (22, 80, 443)

from_list = tuple(['i-123', 'i-456'])     # list -> tuple
from_string = tuple('aws')                  # 'aws' -> ('a', 'w', 's')

# packing / unpacking
instance_specs = 'm5.large', 2, 8.0         # packing (parens optional)
instance_type, vcpus, memory = instance_specs   # unpacking
```

## 🔒 Immutability — What Actually Can't Change

```python
config = ('api.example.com', 443, True)
# config[1] = 80   # ❌ TypeError: 'tuple' object does not support item assignment
```

The variable can still be **reassigned** to a brand-new tuple — that's not the same as modifying the original:

```python
ports = (22, 80, 443)
ports = ports + (8080,)    # creates a NEW tuple, rebinds the variable — original (22,80,443) is untouched
print(ports)                # (22, 80, 443, 8080)
```

| Action                    | Allowed? | Why                                       |
| -------------------------- | -------- | -------------------------------------------- |
| `t = (1, 2, 3)`             | ✅        | creating a tuple                              |
| `t[0] = 99`                 | ❌        | tuples don't support item assignment         |
| `t = (4, 5, 6)`              | ✅        | reassigning the variable, not the old tuple  |
| `t += (7,)`                  | ✅        | builds a new tuple and rebinds `t`            |

## 🧰 Tuple Methods & Operations

Tuples only have two methods (no add/remove — they're immutable), plus operators:

| Method/Op          | What it does                | Example                              |
| -------------------- | ------------------------------ | ----------------------------------------- |
| `.count(x)`           | occurrences of `x`              | `('run','stop','run').count('run')` → `2` |
| `.index(x)`           | position of first match         | `('ssh','http').index('http')` → `1`      |
| `t1 + t2`              | concatenate into a new tuple     | `(22,80) + (443,)` → `(22,80,443)`         |
| `t * n`                | repeat elements                  | `('tmp',) * 3` → `('tmp','tmp','tmp')`     |
| `x in t`               | membership test                  | `'us-east-1' in AWS_REGIONS`               |
| `len(t)`               | number of elements               | `len(ports)`                                |

## 📦 Unpacking

```python
instance_id, instance_type, az = ('i-123456', 't2.micro', 'us-east-1a')

# extended unpacking — grab first, last, and "everything else"
ports = (22, 80, 443, 8080, 9000)
first, *middle, last = ports
print(first, middle, last)   # 22 [80, 443, 8080] 9000

# ignore values you don't need
instance_id, _, _, az, _ = ('i-123', 'running', 't2.micro', 'us-east-1a', '2024-01-01')
```

## 🏷 Named Tuples

`namedtuple` (from `collections`) gives tuples field names — more readable than index-based access, still immutable.

```python
from collections import namedtuple

EC2Instance = namedtuple('EC2Instance', ['id', 'type', 'state', 'az'])
web = EC2Instance(id='i-123', type='t2.micro', state='running', az='us-east-1a')

print(web.id, web.state)   # by name
print(web[1])                # by index — 't2.micro'
```

## ⚖️ Tuple Comparison

Python compares tuples element-by-element, left to right — this is exactly how version numbers behave:

```python
print((1, 5, 3) < (1, 6, 0))    # True — 5 < 6 decides it
print((1, 2, 0) < (1, 2, 1))    # True — 0 < 1
print((1, 4) < (1, 4, 1))        # True — shorter tuple is "smaller" when the shared prefix is equal
print((1, 4, 5) == (1, 4, 5))    # True — all elements match
```

## ⚖️ Tuples vs Lists

| Use a `tuple` when...              | Use a `list` when...             |
| -------------------------------------- | ------------------------------------- |
| the data must never change             | you need to add/remove items later    |
| you need it as a dict key              | order/content will change over time   |
| returning multiple values from a func  | building up a collection in a loop    |
