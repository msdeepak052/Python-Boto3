## 🖐 5 Hands-On Exercises — Pick the Right Type

Each scenario below is solved with the reasoning shown, so you can see *why* a type was picked, not just which one.

### 1. A fixed list of allowed deployment regions

**Scenario:** These regions never change at runtime — only a code change should update them.

```python
ALLOWED_REGIONS = ('us-east-1', 'us-west-2', 'eu-west-1')   # tuple
```
**Why:** the data must never be modified accidentally — immutability is the deciding factor, so `tuple` over `list`.

---

### 2. Checking if an incoming port is allowed by the firewall

**Scenario:** This check runs on every incoming request — performance matters.

```python
allowed_ports = {22, 80, 443}   # set
if port in allowed_ports:       # O(1), not O(n)
    allow_traffic(port)
```
**Why:** frequent membership testing (`in`) is O(1) for a `set` vs O(n) for a `list` — pick `set` whenever you're checking "is X in this collection?" a lot.

---

### 3. Looking up full instance details by instance ID

**Scenario:** You constantly need "given this ID, give me everything about it."

```python
instance_map = {"i-101": {"type": "t2.micro", "state": "running"}}   # dict
print(instance_map["i-101"]["state"])
```
**Why:** you're accessing by a meaningful key (not position), so `dict` — not `list`, which would force you to search.

---

### 4. A deployment step queue you'll pop items off of

**Scenario:** Steps run in order, and completed steps get removed from the queue.

```python
deploy_steps = ['build', 'test', 'deploy']   # list
while deploy_steps:
    step = deploy_steps.pop(0)
    run(step)
```
**Why:** order matters, and the collection needs to shrink as you process it — `list` is mutable and ordered, `tuple`/`set` wouldn't work here.

---

### 5. A cache key built from a set of allowed regions

**Scenario:** You want to cache a rate limit value keyed by *which combination* of regions a request touches — but a `set` can't be a dict key.

```python
region_limits = {
    frozenset(['us-east-1', 'eu-west-1']): 100,   # frozenset — hashable, usable as a key
}
print(region_limits[frozenset(['us-east-1', 'eu-west-1'])])   # 100
```
**Why:** you need set-like uniqueness *and* hashability (to use as a dict key) — regular `set` isn't hashable, `frozenset` is.

## 📊 Comparison Table

| Data Type    | Mutable? | Ordered? | Unique elements? | Syntax            | Access       |
| ------------- | -------- | -------- | ------------------ | -------------------- | -------------- |
| `list`         | ✅ Yes    | ✅ Yes    | ❌ No                | `[1, 2, 3]`            | by index          |
| `tuple`        | ❌ No     | ✅ Yes    | ❌ No                | `(1, 2, 3)`            | by index          |
| `dict`         | ✅ Yes    | ✅ (3.7+) | keys: ✅              | `{'key': 'value'}`      | by key             |
| `set`          | ✅ Yes    | ❌ No     | ✅ Yes                | `{1, 2, 3}`             | membership only    |
| `frozenset`    | ❌ No     | ❌ No     | ✅ Yes                | `frozenset({1, 2})`     | membership only    |

---

## 🧭 Decision Rules

- **Order + will change over time** → `list`
- **Order + must never change** → `tuple`
- **Look up by name/key, not position** → `dict`
- **Only care "is X present?", duplicates unwanted** → `set`
- **Same as `set`, but need it hashable (as a dict key, or inside another set)** → `frozenset`

**Performance shortcut:** membership testing (`x in collection`) is O(1) for `set`/`dict`/`frozenset`, but O(n) for `list`/`tuple` — swap to a set-based type the moment you're checking membership in a loop.
